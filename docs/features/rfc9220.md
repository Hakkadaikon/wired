# RFC 9220: HTTP/3 を用いた WebSocket のブートストラップ

仕様の本文(`tasks/specs/rfc9220.txt`。git には含まない)から抽出した EARS 形式の要件台帳です。RFC 9220 は、HTTP/2 向けに定義された RFC 8441 の Extended CONNECT の仕組みを HTTP/3 に合わせる短い文書です。この SDK は Extended CONNECT の仕組みそのもの(`:protocol` 擬似ヘッダーと SETTINGS_ENABLE_CONNECT_PROTOCOL 設定)を実装しており、WebTransport([draft-ietf-webtrans-http3](draft-webtrans-http3.md) を参照)はその上に成り立っています。各要件には、それを確かめるテストを付けています。チェックがなくテスト行もない項目は、未解決のギャップです。2026-10 時点の状況です。

凡例:

- `[x]`: 挙げたテストで確認済み
- `[~]`: 間接的に確認(専用のテストはなく、evidence 行で確かめ方を説明)
- `[ ]`: まだどのテストでも確認していない

**カバレッジ: テスト済み 9/10、間接 1、未テスト 0。**

- [~] 9220-009 (§3) Extended CONNECT ストリームの HTTP/3 ストリームのクローズは、TCP 接続のクローズと同様でなければならない。正常なクローズはストリーム上の FIN で表し、突然のクローズは H3_REQUEST_CANCELLED 型のストリームエラーで表す。
  - evidence: CONNECT ストリームの FIN またはリセットを受信すると、トンネルが閉じる(`tests/app/srvrun_test.c` — `test_srvrun_connect_stream_reset_closes_wt_session`)。汎用のリクエスト取り消しビルダーは H3_REQUEST_CANCELLED を出力する(`tests/app/h3cancel_test.c` — `test_h3cancel_request_builds_both_frames`)。ただし、Extended CONNECT ストリーム上でそれを動かすテストはない。WebSocket のトンネルは実装しておらず、WebTransport はこれらの中断コードを独自のものに置き換える。
- [x] 9220-010 (§3) Extended CONNECT がサーバーの認識しない `:protocol` の値を持つ場合、サーバーはそれに対して WebTransport セッションを確立してはならない。
  - test: `tests/app/srvrun_test.c` —
    `test_srvrun_wt_connect_unsupported_protocol_gets_501`
  - evidence: `srvrun_is_wt_connect` が認識するのは `webtransport`/`webtransport-h3` のトークン(`wt_protocol_is_webtransport`)だけ。

## 対象外

この文書が全面的に RFC 8441 に委ねている要件(RFC 9220 自身は参照するだけで、内容を再掲していない)と、クライアント専用の要件です。

- (§3) `:protocol` 擬似ヘッダーフィールドの完全な意味と、Extended CONNECT での `:path`/`:authority` 擬似ヘッダーフィールドの解釈し直しのうち、RFC 9220 の本文に書かれていない部分。これらは RFC 8441(HTTP/2)で定義され、参照によって「同一」として採り入れられている。RFC 8441 はこの台帳の 3 つの元仕様に含まれず、ここで改めて抽出してはいない。
- (§3) 501 に添える Problem Details 形式の応答(RFC 7807)。任意(MAY)の補足で、この SDK は実装していない。501 そのものは 9220-006 で扱う。
- (§3) クライアント側での SETTINGS_ENABLE_CONNECT_PROTOCOL 設定の解釈と、クライアント側での Extended CONNECT リクエストの組み立て。クライアントの振る舞い。
