# RFC 9220 — Bootstrapping WebSockets with HTTP/3

EARS requirement ledger extracted from the spec text
(`tasks/specs/rfc9220.txt`, not in git). RFC 9220 is a short document that
adapts RFC 8441's Extended CONNECT mechanism (defined for HTTP/2) to
HTTP/3; this SDK implements the Extended CONNECT mechanism itself (the
`:protocol` pseudo-header and the SETTINGS_ENABLE_CONNECT_PROTOCOL
setting), which WebTransport (see
[draft-ietf-webtrans-http3](draft-webtrans-http3.md)) builds on. Each
requirement carries the test that demonstrates it; an unchecked box with no
test line is an open gap. Status as of 2026-10.

Legend:

- `[x]` — demonstrated by the referenced test
- `[~]` — exercised indirectly (evidence line explains how; no dedicated test)
- `[ ]` — not demonstrated by any test yet

**Coverage: 9/10 tested, 1 indirect, 0 untested.**

## §3 WebSockets Upgrade over HTTP/3

- [x] 9220-001 (§3) The implementation shall define the SETTINGS_ENABLE_
  CONNECT_PROTOCOL identifier as 0x08, the same value as HTTP/2.
  - test: `tests/app/qpack_settings_test.c` —
    `test_qpack_settings_connect_protocol_id`
- [x] 9220-002 (§3) Where the server sends SETTINGS_ENABLE_CONNECT_
  PROTOCOL=1, the server shall append it as a SETTINGS pair on the control
  stream.
  - test: `tests/app/h3settings_build_test.c` —
    `test_h3settings_build_connect_protocol`
  - test: `tests/app/h3settings_control_settings_test.c` —
    `test_h3settings_control_settings_advertises_connect_protocol`
- [x] 9220-003 (§3) The implementation shall recognize the `:protocol`
  pseudo-header field on an Extended CONNECT request.
  - test: `tests/app/connect_test.c` — `test_connect_protocol_present`
  - test: `tests/app/connect_test.c` — `test_connect_protocol_absent`
  - test: `tests/app/pseudo_encode_test.c` —
    `test_pseudo_protocol_roundtrip`
  - test: `tests/app/pseudo_encode_test.c` —
    `test_pseudo_protocol_omitted`
- [x] 9220-004 (§3) If a server receives a `:protocol` pseudo-header
  field but has not sent SETTINGS_ENABLE_CONNECT_PROTOCOL with a value of
  1, then the server shall not accept the request as carrying `:protocol`.
  - test: `tests/app/connect_test.c` — `test_connect_protocol_negotiation`
- [x] 9220-005 (§3) The server shall accept an Extended CONNECT request
  whose `:protocol` value it recognizes and supports.
  - test: `tests/app/srvrun_test.c` —
    `test_srvrun_wt_connect_establishes_session`
  - test: `tests/app/srvrun_test.c` —
    `test_srvrun_wt_connect_webtransport_token`
- [x] 9220-006 (§3) If a server advertises support for Extended CONNECT
  but receives an Extended CONNECT request with a `:protocol` value that
  is unknown or unsupported, then the server should respond with a 501
  (Not Implemented) status code.
  - test: `tests/app/srvrun_test.c` —
    `test_srvrun_wt_connect_unsupported_protocol_gets_501`
  - evidence: `srvrun_is_wt_connect_unsupported_protocol` detects an
    Extended CONNECT whose `:protocol` is not a recognized WebTransport
    token, and `srvrun_non_wt_status` returns 501 for it before the
    request reaches the app handler.
- [x] 9220-007 (§3) The Extended CONNECT request's `:scheme`, `:authority`,
  and `:path` pseudo-header fields shall carry the semantics defined for
  Extended CONNECT rather than being forbidden as in plain CONNECT.
  - test: `tests/app/srvrun_test.c` —
    `test_srvrun_wt_connect_missing_scheme_no_session`
  - test: `tests/app/srvrun_test.c` —
    `test_srvrun_wt_connect_missing_path_no_session`
  - test: `tests/app/srvrun_test.c` —
    `test_srvrun_wt_connect_missing_authority_no_session`
- [x] 9220-008 (§3) The server shall reject an Extended CONNECT request
  missing any of `:scheme`, `:authority`, or `:path`.
  - test: `tests/app/srvrun_test.c` —
    `test_srvrun_wt_connect_missing_scheme_no_session`
  - test: `tests/app/srvrun_test.c` —
    `test_srvrun_wt_connect_missing_path_no_session`
  - test: `tests/app/srvrun_test.c` —
    `test_srvrun_wt_connect_missing_authority_no_session`
- [~] 9220-009 (§3) The HTTP/3 stream closure of an Extended CONNECT
  stream shall be analogous to a TCP connection closure: an orderly close
  is a FIN on the stream, and an abrupt close is a stream error of type
  H3_REQUEST_CANCELLED.
  - evidence: a FIN or reset of the CONNECT stream closes the tunnel on
    receive (`tests/app/srvrun_test.c` —
    `test_srvrun_connect_stream_reset_closes_wt_session`), and the generic
    request-cancel builder emits H3_REQUEST_CANCELLED
    (`tests/app/h3cancel_test.c` —
    `test_h3cancel_request_builds_both_frames`), but no test drives it on
    an Extended CONNECT stream; WebSocket tunnels are not implemented and
    WebTransport replaces these abort codes with its own.
- [x] 9220-010 (§3) If an Extended CONNECT carries a `:protocol` value the
  server does not recognize, then the server shall not establish a
  WebTransport session for it.
  - test: `tests/app/srvrun_test.c` —
    `test_srvrun_wt_connect_unsupported_protocol_gets_501`
  - evidence: `srvrun_is_wt_connect` only recognizes the
    `webtransport`/`webtransport-h3` tokens (`wt_protocol_is_webtransport`).

## Out of scope

Requirements this document defers entirely to RFC 8441 (referenced, not
reproduced, by RFC 9220 itself) or that are client-only:

- (§3) The full semantics of the `:protocol` pseudo-header field and the
  `:path`/`:authority` pseudo-header field reinterpretation under Extended
  CONNECT, beyond what RFC 9220's own text states, are defined in RFC 8441
  (HTTP/2) and adopted "identical" by reference; RFC 8441 is not one of
  this ledger's three source specs and is not separately re-extracted here.
- (§3) Problem-details responses (RFC 7807) accompanying a 501 — optional
  (MAY) elaboration this SDK does not ship; the 501 itself is 9220-006.
- (§3) Client-side interpretation of the SETTINGS_ENABLE_CONNECT_PROTOCOL
  setting and client-side Extended CONNECT request construction — client
  behavior.
