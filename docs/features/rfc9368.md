# RFC 9368: QUIC のための互換性のあるバージョンネゴシエーション

仕様の本文(`tasks/specs/rfc9368.txt`。git には含まない)から抽出した EARS 形式の要件台帳です。対象はサーバー側に限ります。各要件には、それを確かめるテストを付けています。チェックがなくテスト行もない項目は、未解決のギャップです。2026-10 時点の状況です。

範囲についての注記: サーバーは v1 と v2(RFC 9369)をサポートします。クライアントの version_information が、互換性がありサポートされているバージョンを Chosen Version より前に挙げているとき、サーバーは応答全体をそのバージョンに切り替えます(互換性のあるバージョンネゴシエーション)。そうでなければ、クライアントの最初のフライトが使ったバージョンで応答します。

凡例:

- `[x]`: 挙げたテストで確認済み
- `[~]`: 間接的に確認(専用のテストはなく、evidence 行で確かめ方を説明)
- `[ ]`: まだどのテストでも確認していない

**カバレッジ: テスト済み 20/25、間接 5、未テスト 0。**

## §2 バージョンネゴシエーションの仕組み

- [x] 9368-001 (§2) 最初のフライトを、それが届いたバージョンで解析できるとき、サーバーはクライアントの Chosen Version を使って接続を確立しなければならない。
  - test: `tests/app/srvboot_version_test.c` —
    `test_srvboot_accept_v2_initial`
  - test: `tests/app/srvboot_version_test.c` — `test_vneg_not_owed_for_v2`

## §2.1 互換性のないバージョンネゴシエーション

- [x] 9368-002 (§2.1) クライアントの最初のフライトのバージョンを解析できない場合、サーバーは Version Negotiation パケットを送信して、互換性のないバージョンネゴシエーションを始めなければならない。
  - test: `tests/app/srvboot_version_test.c` —
    `test_vneg_owed_for_alien_version`
- [x] 9368-003 (§2.1) サーバーは、自身の Offered Versions の各エントリを、Version Negotiation パケットの Supported Version フィールドに含めなければならない。
  - test: `tests/app/srvboot_version_test.c` — `test_vneg_lists_v1_and_v2`
- [~] 9368-004 (§2.1) サーバーは、受信したすべての Version Negotiation パケットを無視しなければならない。
  - evidence: Version が 0 のデータグラムは、サーバーの VN のきっかけ(`srvboot_vn_alien` はバージョン 0 に 0 を返す)からも、Initial の受け入れ判定(`wired_srvboot_is_initial` が拒否する)からも外れます。VN パケットをサーバーに与える専用のユニットテストはありません。

## §2.2 互換性のあるバージョン

- [x] 9368-005 (§2.2) サーバーは、明示的に定められていない限り、2 つのバージョンの間に互換性があるとみなしてはならない(v1 と v2 は互換性があり、未知の組は互換性がない)。
  - test: `tests/transport/compat_test.c` — `test_v1_v2_compatible`
  - test: `tests/transport/compat_test.c` — `test_unknown_incompatible`

## §2.3 互換性のあるバージョンネゴシエーション

- [x] 9368-006 (§2.3) クライアントの Available Versions から選ぶとき、サーバーは、自身がサポートし、かつクライアントの Chosen Version と互換性のあるバージョンだけを選ばなければならない。
  - test: `tests/transport/verselect_test.c` —
    `test_verselect_pick_client_order`
  - test: `tests/transport/verselect_test.c` — `test_verselect_pick_v2_first`
  - test: `tests/transport/verselect_test.c` — `test_verselect_none`
  - test: `tests/app/srvboot_version_test.c` —
    `test_srvboot_v1_initial_with_vi_switches_to_v2`
  - vuln: V-0227
- [x] 9368-007 (§2.3, §3) 使うバージョンを選ぶとき、サーバーは予約済み(0x?a?a?a?a)のバージョンを決して選んではならない。
  - test: `tests/transport/verselect_test.c` — `test_verselect_skips_grease`
  - test: `tests/transport/availfilter_test.c` —
    `test_availfilter_grease_excluded`
  - vuln: V-0227
- [~] 9368-008 (§2.3) クライアントの最初のフライトを Negotiated Version に変換できない場合、サーバーはハンドシェイクを中止しなければならない。
  - evidence: サーバーが行う変換は v1 <-> v2 だけで、これは解析済みの同じ ClientHello を封じ直すものなので、テストすべき失敗の分岐がありません(`tests/app/srvboot_version_test.c` — `test_srvboot_v1_initial_with_vi_switches_to_v2` が切り替えの成功を示します)。変換できない最初のフライトを与えるテストはありません。
- [x] 9368-009 (§2.3) 互換性のあるバージョン(クライアントの Chosen Version を含む)が見つからない場合、サーバーは代わりに互換性のないバージョンネゴシエーションを行わなければならない。
  - test: `tests/app/srvboot_version_test.c` —
    `test_vneg_owed_for_alien_version`
- [x] 9368-025 (§2.3, §8) Negotiated Version を選んだあと、サーバーは、そのバージョンに変換したクライアントの最初のフライトを受信したかのようにクライアントへ応答しなければならない。
  - test: `tests/app/srvboot_version_test.c` —
    `test_srvboot_v1_initial_with_vi_switches_to_v2`
  - test: `tests/app/h3_loopback_test.c` —
    `test_srvboot_hrr_v2_switch_accepts_ch2_with_v1_chosen`
  - vuln: V-0227
- [~] 9368-024 (§2.3) Negotiated Version がハンドシェイクパケットの検証を義務づけている場合、サーバーは変換した最初のフライトに対してもその検証を行わなければならない。
  - evidence: このサーバーがネゴシエートするバージョンは v1 と v2 だけで、RFC 9369 §3 による両者の違いは定数だけです。そのため検証(ハンドシェイク中に 5 タプルが変わらないという RFC 9000 の検証を含む)は、元のフライトにも変換したフライトにも同じコードで行います。変換したフライトに対する v2 固有の検証を固定するテストはありません。

## §3 バージョン情報

- [x] 9368-010 (§3, §10.1) サーバーは Version Information を version_information トランスポートパラメーター(0x11)として交換しなければならない。
  - test: `tests/transport/version_test.c` — `test_version_info_roundtrip`
- [x] 9368-011 (§3) 実装は Version Information を、32 ビットの Chosen Version と、それに続く 32 ビットの Available Versions としてエンコード・デコードしなければならない。それぞれネットワークバイト順である。
  - test: `tests/transport/verinfo_test.c` — `test_verinfo_roundtrip`
  - test: `tests/transport/verinfo_test.c` — `test_verinfo_wire_be`
- [x] 9368-012 (§3) 実装は、サーバーが送る Version Information に許されているとおり、Available Versions フィールドが空の(Chosen Version だけの)Version Information を正しい形式として扱わなければならない。
  - test: `tests/transport/verinfo_test.c` — `test_verinfo_chosen_only`
- [~] 9368-023 (§3, §5) サーバーは、Chosen Version を Negotiated Version に、Available Versions を自身の Fully Deployed Versions にした自身の Version Information を送信しなければならない。
  - evidence: `sdrv_flight_emit_ee_version_info` がサーバーのすべてのフライトでこれを出力します。interop のテストケース `v2` はサーバーの Version Information を検証する ngtcp2 と picoquic を相手に通っています([相互接続性](../interop.md)を参照)。出力したパラメーターをデコードするユニットテストはありません。

## §4 バージョンのダウングレード防止

- [x] 9368-013 (§4) ピアの Version Information が短すぎるか、その長さが 4 で割り切れない場合、サーバーはそれを解析の失敗として扱い、拒否しなければならない。

  - test: `tests/transport/version_test.c` — `test_version_info_truncated`
- [x] 9368-014 (§4) ピアの Version Information の解析に失敗した場合、サーバーは TRANSPORT_PARAMETER_ERROR 型のトランスポートエラーで接続を閉じなければならない。
  - test: `tests/tls/sdrv_test.c` —
    `test_sdrv_recv_client_hello_version_information_malformed_rejected`
- [x] 9368-015 (§4) ゼロに等しい Chosen Version、またはゼロに等しい Available Version を受信した場合、サーバーはその Version Information を解析の失敗として扱わなければならない。
  - test: `tests/tls/sdrv_test.c` —
    `test_sdrv_recv_client_hello_version_information_invalid_entries`
  - test: `tests/transport/verinfo_test.c` — `test_verinfo_decode_bad`
- [x] 9368-016 (§4) クライアントの Chosen Version がその Available Versions に含まれていない場合、サーバーはその Version Information を解析の失敗として扱わなければならない。

- [x] 9368-022 (§4) クライアントの Chosen Version が使用中のバージョンと異なる場合、サーバーは VERSION_NEGOTIATION_ERROR で接続を閉じなければならない。
  - test: `tests/tls/sdrv_test.c` —
    `test_sdrv_recv_client_hello_chosen_mismatch_vn_error`

- [x] 9368-018 (§4, §10.2) サーバーは VERSION_NEGOTIATION_ERROR (0x11) を、バージョンネゴシエーションのエラーを伝える標準のトランスポートエラーコードとして認識しなければならない。

## §5 QUIC のサーバー展開

- [x] 9368-020 (§5) サーバーは、サポートする(Fully Deployed の)バージョンの集合 v1 と v2 を保持し、それ以外のバージョンをサポートしないものとして扱わなければならない。
  - test: `tests/transport/avail_test.c` — `test_avail`

## §6 アプリケーション層プロトコルの考慮事項

- [~] 9368-021 (§6) サーバーは、接続のために選ぶ QUIC バージョンの上で動く ALPN トークンだけを選ばなければならない。
  - evidence: `sdrv_negotiate_alpn` は、設定した生の ID、h3、hq-interop の中から QUIC バージョンを見ずに選びます。そのどれも v1 と v2 の両方で定義されています(RFC 9369 §7)。サーバーは v2 の Initial パケットを受け入れます(`test_srvboot_accept_v2_initial`)。v2 の上で ALPN を最後までネゴシエートするテストはありません。

## 対象外

このサーバー SDK が実装しない、クライアントだけの要件と運用者レベルの要件です。カバレッジの分母から除いています。

- (§1.2) 推奨(RECOMMENDED)される 1 分の Maximum Segment Lifetime。§5 の運用者による展開のペースを決めるだけです。
- (§1.2, §2.5) クライアントによる Original Version の選択。クライアントの動作です。
- (§2.1) クライアントによる Version Negotiation パケットの処理(一覧の検索、中止、共通のバージョンの選択、新しい最初のフライトの送信)。クライアントの動作です。
- (§2.1) 「クライアントは Version Negotiation パケットを送信してはならない(MUST NOT)」。クライアントの動作です。
- (§2.4) 互換性のないネゴシエーションの、2 つの接続による概念上のモデル。説明のためのもので、実装への要件はありません。
- (§2.3) 互換性のあるバージョンを定める文書は、クライアントが Negotiated Version を知る方法を規定しなければならず、その仕組みを共有するべきであるという規定。仕様の作者に対する要件です。
- (§3) クライアントが送る Available Versions の中身と優先順位。クライアントの動作です。
- (§4) クライアント側のダウングレードの検証(Original Version を含む VN パケットの無視、サーバーの Available Versions の検証、サーバーの Chosen Version == Negotiated Version の要求、VN への対応後にサーバーの Version Information がないときに接続を閉じること)。クライアントの動作です。
- (§5) サーバー群全体でバージョンを追加・削除するための、運用者による 3 段階の展開。運用者向けの指針です。
- (§6) 互換性のないネゴシエーションのあとの 2 つ目の接続で ALPN のネゴシエーションをやり直すこと。クライアントが主導するもので、サーバーは 2 つの接続をまたいで状態を持たないため、それぞれの接続が ALPN を新たにネゴシエートします。
- (§7) 将来の QUIC バージョンのための設計上の考慮事項(仮想の互換バージョンにおける Retry、TLS 再開、0-RTT との相互作用)。仕様の作者に向けた指針です。
- (§8) Version Negotiation パケットに対応するときに、サーバーの version_information がなければ v1 とみなすこと。クライアントの動作です。
- (§10) IANA への登録。登録の手続きで、実装の対象ではありません。
