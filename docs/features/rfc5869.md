# RFC 5869: HMAC ベースの抽出・展開による鍵導出関数(HKDF)

- `[x]`: 挙げたテストで確認済み

## 対象外

このサーバー SDK が実装しない、クライアント専用または運用者向けの要件です。カバレッジの分母から除きます。

- (§2) SHA-256 と SHA-384 以外のハッシュ関数でインスタンス化した HKDF。SDK の TLS 1.3/QUIC の暗号スイートに必要なのはこの 2 つだけ。
- (§3.1) salt の値の選び方や与え方の指針。アプリケーション設計の指針であり、TLS 1.3 の鍵スケジュールが salt を決めている。
- (§3.2) 'info' 入力の内容についての指針。アプリケーション設計の指針であり、RFC 8446 が HkdfLabel の構造を決めている。
- (§3.3) 抽出の手順を省くことと、Diffie-Hellman の入力についての SHOULD NOT。呼び出し側の鍵スケジュールの関心事であり、RFC 8446 は常に抽出する。
- (§3.3) PRK をそのまま OKM として使うこと(NOT RECOMMENDED)。呼び出し側への指針。
- (§4) パスワードからの鍵導出(低速な KDF)。アプリケーションの関心事であり、ここでは HKDF をパスワードに使わない。
- (§3.4) IKM と salt の出どころを独立させること。運用者またはアプリケーションの関心事。
- (A.4–A.7) SHA-1 のテストベクター。SDK は SHA-1 を実装していない。
