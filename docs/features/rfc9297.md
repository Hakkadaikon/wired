## §2 HTTP データグラム

- [x] 9297-001 (§2) サーバーは、HTTP データグラムを明示的にサポートするリクエストに関連付けた HTTP データグラムだけを送信しなければならない。
  - test: `tests/app/srvrun_test.c` —
    `test_srvrun_wt_send_datagram_to_requires_established`
  - test: `tests/app/srvrun_test.c` —
    `test_srvrun_wt_send_datagram_to_requires_send_side_open`
  - evidence: `srvrun_wt_datagram_request_type_ok`(srvrun.c)がこの条件の判定を明示しています。wired_server_wt_send_datagram_to の引数の型(`wired_wt_session*`)によって、リクエストの種類との関連付けはすでにコンパイル時の制約になっています(WebTransport 以外のレスポンスの種類からはセッションを渡せない)。この述語は実行時の側を補い、セッションが ESTABLISHED/DRAINING に達していること(サーバーが 2xx を送信済みであること)を求めます。
- [x] 9297-002 (§2) HTTP データグラムを受信し、それが HTTP データグラムの意味を定めていないリクエストに関連付けられている場合、サーバーはそのリクエストを H3_DATAGRAM_ERROR (0x33) で終了しなければならない。
  - test: `tests/app/srvrun_test.c` —
    `test_srvrun_rx_datagram_unknown_semantics_aborts_stream`

## 対象外

このサーバー SDK が実装しない、クライアントだけ・中継者だけの要件と、HTTP のバージョンに固有の要件です。カバレッジの分母から除いています。

- (§1) HTTP/1.x と HTTP/2 での HTTP データグラムのサポート。この SDK は HTTP/3 専用のサーバーです。
- (§2.2) QUIC DATAGRAM フレームを使えないときに、カプセルプロトコルを唯一の転送手段として HTTP データグラムをネゴシエートし運ぶこと。この SDK では QUIC DATAGRAM を常に使えるので(RFC 9221)、HTTP データグラムのカプセルだけによる代替経路は実装していません。
- (§2.1.1) サーバーの SETTINGS_H3_DATAGRAM の値を 0-RTT のために保存し、再開時の値をそれと照合するクライアントの動作。クライアントの動作です。
- (§3) カプセルと HTTP データグラムに対する中継者の転送・再エンコード・変換の動作(§3.2 の中継者は転送するべきであるという指針、§3.5 の QUIC DATAGRAM からカプセルへの再エンコードの経験則)。この SDK はエンドポイントであり、HTTP の中継者ではありません。
- (§3.1) 「データストリーム」の概念の HTTP/1.x 固有と HTTP/2 固有の定義。この SDK は HTTP/3 専用です。
- (§2, §2.1) データグラムの関連付けの規則を上書きする HTTP 拡張と、拡張が定めるデータグラムの優先度付け。任意(MAY)で、WebTransport は使いません。
- (§3.5) 新しい HTTP 拡張はカプセルプロトコルを使うべきである(SHOULD)という規定。拡張の作者に向けた指針で、実装に向けたものではありません。
- (§4) 「目立つこと」と JavaScript の Web Platform API からの利用可能性についてのセキュリティ上の考慮の指針。参考情報で、テストできるサーバーの動作ではありません。
