# RFC 8999: QUIC のバージョンに依存しない性質

仕様の本文(`tasks/specs/rfc8999.txt`。git には含まない)から抽出した EARS 形式の要件台帳です。各要件には、それを確かめるテストを付けています。チェックがなくテスト行もない項目は、未解決のギャップです。2026-10 時点の状況です。

凡例:

- `[x]`: 挙げたテストで確認済み
- `[~]`: 間接的に確認(専用のテストはなく、evidence 行で確かめ方を説明)
- `[ ]`: まだどのテストでも確認していない

**カバレッジ: テスト済み 14/16、間接 2、未テスト 0。**

## §5 QUIC パケット

- [x] 8999-001 (§5) 実装は最初のバイトの最上位ビットが 1 のパケットをロングヘッダーのパケット、0 のパケットをショートヘッダーのパケットとして分類しなければならない。
  - test: `tests/transport/header_test.c` — `test_header_parse_long`
  - test: `tests/transport/header_test.c` — `test_header_parse_short`
  - vuln: V-0162, V-0163

## §5.1 ロングヘッダー

- [x] 8999-002 (§5.1) 実装はロングヘッダーを、最初のバイト、32 ビットの Version、8 ビットの Destination Connection ID Length とその長さ分の DCID のバイト、8 ビットの Source Connection ID Length とその長さ分の SCID のバイト、バージョン固有のデータ、として解析しなければならない。
  - test: `tests/transport/header_test.c` — `test_header_parse_long`
  - test: `fuzz/fuzz_header.c` — `LLVMFuzzerTestOneInput`
  - vuln: V-0162, V-0163
- [x] 8999-003 (§5.1) ロングヘッダーを組み立てるとき、実装は解析すると入力が再現されるように、同じ不変のレイアウトで出力しなければならない。
  - test: `tests/transport/header_test.c` — `test_header_build_roundtrip`
  - test: `tests/transport/lhdr_build_test.c` — `test_lhdr_initial_layout`
  - vuln: V-0162, V-0163
- [x] 8999-004 (§5.1) ロングヘッダーが途中で切れている(Version フィールドや、長さを宣言した接続 ID がデータグラムの終わりを越える)場合、実装はバッファーの外を読まずにそのパケットを拒否しなければならない。
  - test: `tests/transport/header_test.c` — `test_header_truncated`
  - test: `tests/transport/header_test.c` —
    `test_header_long_too_short_for_version`
  - vuln: V-0053
- [x] 8999-016 (§5.1) サポートしないバージョンの不変ヘッダーを解析するとき、実装は 0 から 255 バイトまでの任意の長さのロングヘッダーの Destination Connection ID と Source Connection ID を受け入れなければならない。
  - test: `tests/app/h3_loopback_test.c` —
    `test_srvboot_vneg_echoes_255_byte_cids` (`wired_srvboot_vneg`, which
    `srvrun_vneg` calls, reads both IDs as 0..255-byte views and echoes
    them; `srvrun_vneg`'s buffer is `WIRED_SRVBOOT_VN_MAX`)

## §5.2 ショートヘッダー

- [x] 8999-005 (§5.2) 実装はショートヘッダーの最初のバイトのすぐあとに Destination Connection ID を置き、Version、長さ、Source Connection ID のフィールドを置いてはならない。

## §6 バージョンネゴシエーション

- [x] 8999-009 (§6) サーバーがサポートしないバージョンのロングヘッダーのデータグラムが届いたとき、サーバーは Version Negotiation パケットで応答しなければならない。この応答は RFC 8999 が許し、RFC 9000 §6.1 が求めるものである。
  - test: `tests/app/srvboot_version_test.c` —
    `test_vneg_owed_for_alien_version`
  - test: `tests/app/h3_loopback_test.c` —
    `test_srvboot_vneg_responds_to_alien_version`
- [x] 8999-010 (§6) サーバーは自分がサポートするバージョンのパケットに対して Version Negotiation パケットを送ってはならない。
  - test: `tests/app/srvboot_version_test.c` — `test_vneg_not_owed_for_v2`
  - test: `tests/app/h3_loopback_test.c` — `test_srvboot_vneg_guards`
- [x] 8999-011 (§6) サーバーはショートヘッダーのパケットに対して Version Negotiation パケットを送ってはならない。
  - test: `tests/app/h3_loopback_test.c` — `test_srvboot_vneg_guards`
- [x] 8999-012 (§6) サーバーは最初のバイトの最上位ビットを 1 にし、Version フィールドを 0x00000000 にして、両方の接続 ID と Supported Version フィールドのリストだけを持つ Version Negotiation パケットを組み立てなければならない。
  - test: `tests/transport/packet2_test.c` — `test_vneg_roundtrip`
  - test: `tests/app/h3_loopback_test.c` —
    `test_srvboot_vneg_responds_to_alien_version`
- [~] 8999-013 (§6) Version Negotiation パケットを受信したとき、実装は最初のバイトの 7 つの Unused ビットを無視しなければならない。
  - evidence: サーバーは受信した Version Negotiation パケットをすべて無視する(RFC 9368 §2.1、9368-004)ので、その Unused ビットを読むことはない。受信側のパーサー `vneg_parse` は形式ビットだけを検査するが、`src/` からの呼び出し元がない。
- [~] 8999-014 (§6) 実装は Supported Version フィールドを 1 つも含まない Version Negotiation パケットや、Supported Version の値が途中で切れている Version Negotiation パケットを無視しなければならない。
  - evidence: 8999-013 と同じ(受信した VN パケットはすべて無視する)。`vneg_parse` のバージョンが欠けずにそろっているかの検査(`versions_whole`)はどこにもつながっておらず、解析側のテストもない。
- [x] 8999-015 (§6) Version Negotiation パケットを送るとき、サーバーは受信した Source Connection ID を Destination Connection ID フィールドに、受信した Destination Connection ID を Source Connection ID フィールドにコピーしなければならない。
  - test: `tests/transport/packet2_test.c` — `test_vneg_respond_swap`
  - test: `tests/app/h3_loopback_test.c` —
    `test_srvboot_vneg_responds_to_alien_version`

## 対象外

このサーバー SDK が実装しない、クライアント専用または運用者向けの要件です。カバレッジの分母から除きます。

- (§3) この文書が将来の QUIC のバージョンと将来の文書に課す要件。仕様を書く側の話で、サーバーのコードではない。
- (§4) 表記の約束事。説明のみ。
- (§6) Version Negotiation パケットを受け取ったあとに新しいバージョンへ切り替えること。クライアントの振る舞い。このサーバーは受信した Version Negotiation パケットを無視する(RFC 9368 §2.1)。
- (§6) Version Negotiation パケットに完全性保護がないこと。参考情報。
- (§7) 別のバージョンを試す前に Version Negotiation パケットの意味内容を認証すること。クライアントの振る舞い。ダウングレード防止のサーバー側は RFC 9368 の台帳で扱う。
- (§7) ミドルボックスによる観測と、特徴の硬直化(ossification)についての考慮事項。参考情報。
- (Appendix A) QUIC バージョン 1 についての誤った思い込みの一覧。参考情報。
