# RFC 6066: TLS 拡張: 拡張定義

仕様の本文(`tasks/specs/rfc6066.txt`。git には含まない)から抽出した EARS 形式の要件台帳です。各要件には、それを確かめるテストを付けています。チェックがなくテスト行もない項目は、未解決のギャップです。この台帳の範囲は、このサーバー SDK が扱う Server Name Indication(§3)です。この RFC が定義するほかの拡張(max_fragment_length、client_certificate_url、trusted_ca_keys、truncated_hmac、status_request)は「対象外」にまとめています。`src/` はどれも実装していません(grep で確認済み)。

凡例:

- `[x]`: 挙げたテストで確認済み
- `[~]`: 間接的に確認(専用のテストはなく、evidence 行で確かめ方を説明)
- `[ ]`: まだどのテストでも確認していない

**カバレッジ: テスト済み 13/14、間接 1、未テスト 0。**

## 対象外

この RFC が定義する拡張のうち、このサーバー SDK が実装していないもの(`src/` にないことを grep で確認済み)です。カバレッジの分母から外しています。

- (§4) Maximum Fragment Length Negotiation: `max_fragment_length` 拡張の処理はありません。レコードの大きさは QUIC 自身のデータグラム・パケットのサイズ決定(RFC 9000 §14、RFC 8899)で決まります。
- (§5) Client Certificate URLs(`client_certificate_url` 拡張と、`CertificateURL`/`CertificateStatus` ハンドシェイクメッセージ): 実装していません。このサーバー SDK は、URL をたどってクライアント証明書を認証することはしません。
- (§6) Trusted CA Indication(`trusted_ca_keys`): 実装していません。
- (§7) Truncated HMAC(`truncated_hmac`): 実装していません。QUIC 1.3 の AEAD スイートは、レコードに HMAC を切り詰める形の MAC を使いません。
- (§8) Certificate Status Request(OCSP stapling、`status_request`): 実装していません。
- (§1, §2) 拡張固有のハンドシェイクメッセージを Finished のハッシュに含めることと、CertificateURL/CertificateStatus のメッセージ型: そうしたメッセージは実装していません。
- (§3) 送信側の規則(クライアントが server_name を送ることの RECOMMENDATION、ASCII・末尾のドットなし・IP リテラルなしの HostName エンコーディング、再開時とアプリケーション層で同じ名前を使い回すこと): クライアントの振る舞いです。サーバーは名前を不透明な値として扱ってかまいません。
- (§3) 16 ビットの長さで始まる将来の NameType: 将来の仕様に向けた規則です。
- (§11.1) TLS の server_name とアプリケーション層の名前が等しいことに依存するアプリケーションサーバーは、両者を比べなければならない: アプリケーションの義務です。SDK はアプリケーションに SNI を公開していません。
- (§9) certificate_unobtainable(111)、bad_certificate_status_response(113)、bad_certificate_hash_value(114): 実装していない §5/§8 のアラートです。
- (§10.1) pkipath MIME タイプのエンコーディング規則: 実装していない §5 に属します。
- (§11.2–§11.6) 上記の対象外の 5 つの拡張に関するセキュリティ上の考慮事項: 拡張自体を実装していないので当てはまりません。
