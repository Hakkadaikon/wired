# RFC 7541: HPACK(HTTP/2 のヘッダー圧縮)

仕様の本文(`tasks/specs/rfc7541.txt`。git には含まない)から抽出した EARS 形式の要件台帳です。各要件には、それを確かめるテストを付けています。チェックがなくテスト行もない項目は、未解決のギャップです。この SDK が話すのは HTTP/3 なので、HPACK を丸ごと使うことはありません。QPACK(RFC 9204)が再利用するのは HPACK の基本的な型、つまりプレフィックス付き整数の表現(§5.1)と、文字列リテラル / ハフマン符号(§5.2、Appendix B)だけです。この台帳は再利用するその部分を扱い、QPACK が置き換える HPACK のインデックスの仕組みは「対象外」にまとめています。2026-11 時点の状況です。

凡例:

- `[x]`: 挙げたテストで確認済み
- `[~]`: 間接的に確認(専用のテストはなく、evidence 行で確かめ方を説明)
- `[ ]`: まだどのテストでも確認していない

**カバレッジ: テスト済み 18/18、間接 0、未テスト 0。**

## §5.1 整数表現

- [x] 7541-001 (§5.1) 2^N-1 未満の整数値をエンコードするとき、実装はその値を N ビットのプレフィックスの中にエンコードしなければならない。
  - test: `tests/app/fieldline_test.c` — `test_fieldline_indexed_golden` (6 ビットのプレフィックスで 17 を表すと 1 オクテットの 0xD1)
  - test: `tests/app/qpack_test.c` — `test_qpack_integer_roundtrip`
- [x] 7541-002 (§5.1) 2^N-1 以上の整数値をエンコードするとき、実装はプレフィックスをすべて 1 で埋め、残りを 7 ビットずつのグループでエンコードしなければならない。最後のオクテット以外は継続ビットを持つ。
  - test: `tests/app/qpack_test.c` — `test_qpack_integer_vector`
  - test: `tests/app/fieldline_test.c` — `test_fieldline_indexed_prefix_boundary` (63 = 2^6-1 は 0xFF 0x00 にエンコードされる)
- [x] 7541-003 (§5.1) デコードするとき、実装は連結した 7 ビットの継続グループに 2^N-1 を足して値を復元しなければならない(5 ビットのプレフィックスの 1337 は 0x1F 0x9A 0x0A からデコードされる。Appendix C.1.2)。
  - test: `tests/app/qpack_test.c` — `test_qpack_integer_vector`
  - test: `tests/app/qpack_test.c` — `test_qpack_integer_roundtrip`
- [x] 7541-004 (§5.1) 実装は QPACK が使う 3 から 8 ビットのプレフィックス長をサポートし、プレフィックスより上にある表現のパターンビットを保たなければならない。
  - test: `tests/app/literal_test.c` — `test_literal_name_prefix_boundary` (3 ビット)
  - test: `tests/app/literal_test.c` — `test_literal_namref_golden` (4 ビット)
  - test: `tests/app/qpack_test.c` — `test_qpack_integer_62bit_boundary` (5 ビットと 7 ビット)
  - test: `tests/app/fieldline_test.c` — `test_fieldline_indexed_prefix_boundary` (6 ビット)
  - test: `tests/app/qpack_prefix_test.c` — `test_qpack_prefix_roundtrip` (8 ビットの Required Insert Count)
- [x] 7541-005 (§5.1) 整数のエンコーディングが最後の継続オクテットの前で切れている場合、実装はそれをデコードエラーとして扱わなければならない。
  - test: `tests/app/qpack_instruction_test.c` — `test_qpack_instr_truncated`
  - test: `tests/app/qpack_prefix_test.c` — `test_qpack_prefix_truncated`
- [x] 7541-006 (§5.1) 整数のエンコーディングが値またはオクテット長で実装の上限を超える場合、実装はそれをデコードエラーとして扱わなければならない。
  - test: `tests/app/qpack_test.c` — `test_qpack_integer_decode_64bit_overflow_rejected` (10 個目の継続グループは `take_group` の 56 ビットのシフト上限で拒否する)
  - vuln: V-0477

## 対象外

QPACK(RFC 9204)が同等の独自の仕組みで置き換える HPACK の仕組みと、HTTP/2 専用の振る舞い、エンコーダーにとって任意の振る舞いです。カバレッジの分母には含めません。

- (§2.1–§2.4, §3) ヘッダーブロックの処理、順序、結合したインデックスのアドレス空間。QPACK はフィールドセクションの処理とインデックスを独自に定義している。
- (§4, §6.3) 動的テーブルの管理、追い出し、動的テーブルサイズの更新命令。QPACK は独自の動的テーブルと命令を持つ。
- (§6.1–§6.2) HPACK のヘッダーフィールドの表現(インデックス付き、およびインデックスあり / インデックスなし / インデックス不可のリテラル)。QPACK のフィールドラインの表現に置き換わっている。
- (Appendix A) HPACK の静的テーブル。QPACK は独自の静的テーブルを定義している。
- (§5.1) 1 ビットと 2 ビットの整数プレフィックス。どの QPACK の表現も使わない。
- (§7.1) 動的テーブルへのプロービングの軽減策と、インデックス不可のリテラルの転送方針。HPACK の動的テーブルは実装しておらず、転送は中継者の関心事。
- (§7.2–§7.3) 静的ハフマンによる情報漏洩の議論と、SETTINGS_HEADER_TABLE_SIZE によるメモリの調整。参考情報、または HTTP/2 の運用者の関心事。
