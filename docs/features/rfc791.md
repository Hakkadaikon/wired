# RFC 791: インターネットプロトコル(IPv4)

仕様の本文(`tasks/specs/rfc791.txt`。git には含まない)から抽出した EARS 形式の要件台帳です。各要件には、それを確かめるテストを付けています。チェックがなくテスト行もない項目は、未解決のギャップです。

範囲: この台帳が扱うのは、wired 自身の AF_XDP 経路(`src/transport/io/socket/net/ipv4.c`、`src/transport/io/xdp/xdpframe/xdpframe.c`)で動く、IPv4 ヘッダーの組み立てと解析、チェックサムの要件だけです。wired はサーバー SDK であり、ゲートウェイではなくエンドポイントです。ルーティング、ゲートウェイによる断片化、オプションは対象外で、黙って省かずに下に挙げています。wired がヘッダーを自分で組み立てるのは AF_XDP 経路だけです。interop の実行ではカーネルの UDP ソケットを使っており、ソケットが IPv4 ヘッダーを自分で組み立てるので、このフレーミングはユニットテスト済みですが、相互接続性の確認では裏付けていません。

凡例:

- `[x]`: 挙げたテストで確認済み
- `[~]`: 間接的に確認(専用のテストはなく、evidence 行で確かめ方を説明)
- `[ ]`: まだどのテストでも確認していない

**カバレッジ: テスト済み 14/16、間接 2、未テスト 0。**

## §3.2 考察

- [x] 791-009 (§3.2) 実装は送信するデータグラムについては保守的に(正しい形式で)、受け入れるデータグラムについては寛容に(意味が明らかな技術的な誤りは拒否せずに)ふるまわなければならない。
  - test: `tests/transport/xdpframe_test.c` —
    `test_xdpframe_rx_accepts_ihl_with_consistent_options`
  - test: `tests/transport/xdpframe_test.c` — `test_xdpframe_rx_rejects`
  - evidence: 送信側(`ipv4_build`、`src/transport/io/socket/net/ipv4.c`)は保守的で、オプションのない固定 20 バイトの IHL=5 のヘッダーを常に組み立てます。これはこの節の「正しい形式」の側に合っています。受信側(`src/transport/io/xdp/xdpframe/xdpframe.c` の `xdpf_ip_ok`/`xdpf_ip_len_ok`/`xdpf_udp`)は、RFC 791 3.1 のとおり IHL >= 5 を受け入れ、実際のヘッダー長を IHL フィールドから計算して、UDP を IP オプションのあとに見つけます。IHL がオプションがあると示しているのに Total Length がその分を含まないデータグラムは、実際の矛盾として拒否します。自己ループバックのテスト(両端がこの SDK 自身の IHL=5 だけを送る)では、IHL > 5 を送るピアを再現できません。
- [x] 791-010 (§1.4, §3.2) Header Checksum の検査に失敗した場合、実装はそのデータグラムをただちに破棄しなければならない。
  - test: `tests/transport/srvxdp_test.c` — `test_srvxdp_rx_drops_bad_headers` (チェックサムのビットを 1 つ反転したフレームでは、UDP チェックサムの検証を外していても `wired_srvxdp_rx_burst` は何も渡さない)

## 対象外

この文書の冒頭の範囲の注記に従い、このサーバー SDK が実装しない、クライアントだけの要件と運用者レベルの要件です。カバレッジの分母から除いています。

- (§3.1) 791-004: Time to Live フィールドを、データグラムの寿命の上限として設定し、処理の各地点で減らすこと。`ipv4_build`(`src/transport/io/socket/net/ipv4.c`)は送信時に固定の TTL 64 を設定します(受信側の「TTL がゼロなら破棄しなければならない」規則は 791-013)。「処理の各地点で減らす」はルーターやゲートウェイの転送の動作を述べたもので、このエンドポイント(ゲートウェイではない)SDK には当てはまりません。下のルーティングとゲートウェイを範囲から外すことと一致しています。
- (§1.4, §2.3, §3.1 Options) Options の仕組み(セキュリティ、緩い/厳密なソースルーティング、経路の記録、タイムスタンプ)と Padding フィールド。ゲートウェイと特殊なルーティングのための制御機能です。wired の AF_XDP 経路はオプションのない固定 20 バイトのヘッダーだけを送ります(受信したオプションに応じて動くことは 791-016)。
- (§3.1 Total Length, §3.2 Fragmentation) 791-014 の再構成の側、つまり断片として届いたデータグラムを受け入れること。AF_XDP 経路での意図的な逸脱です。wired は送信するすべてに DF を設定し(791-012)、RFC 9000 §14 は QUIC エンドポイントに IPv4 で DF を設定することを求め、データグラムのサイズが 1200 バイト未満の経路を禁じています。そのため QUIC のデータグラムが断片化されることは想定していません(RFC 8900 もプロトコルが IP の断片化を避けることを推奨しています)。BPF フィルター(`xdpbpf_prog_build`、`0xff3f` のフラグ/オフセットの判定)はすべての断片を XDP_PASS でカーネルのスタックに渡し、`xdpframe_parse` は MF またはゼロでないオフセットを拒否します(`test_xdpframe_rx_rejects`)。カーネルは断片を再構成しますが、AF_XDP サーバーが読まないポート予約用の UDP ソケットに渡すので、それらは捨てられます。カーネル UDP ドライバー(`--ifindex` なし)は、再構成されたデータグラムを通常どおり受信します。
- (§3.1 Options, §3.2 Options) 791-016、つまり受信したデータグラムが持つすべてのオプションを解析し、それに応じて動くこと。AF_XDP 経路での意図的な逸脱です。BPF フィルターは IHL=5 の固定オフセットで QUIC ヘッダーを読み、IHL != 5 のデータグラムはすべて XDP_PASS でカーネルのスタックに渡します。そこでは(断片と同じく)ポート予約用のソケットがそれを吸収するので、オプションを持つデータグラムが AF_XDP サーバーに届くことはありません。これは、ホストに理解できないオプションを無視したうえでデータグラムを処理するよう求める RFC 1122 §3.2.1.8 より厳しい扱いです。`xdpframe_parse` 自体は IHL > 5 を受け入れ、オプションを解釈せずに読み飛ばします(`test_xdpframe_rx_accepts_ihl_with_consistent_options`)。カーネル UDP ドライバーでは、カーネル自身がオプションを処理します。
- (§1.4, §2.3, §3.2 Fragmentation) データグラムの断片化(ゲートウェイがデータグラムを分割する手順)。wired は送信するものを断片化しません。宛先側の再構成の規則は 791-014、送信側のフラグ/オフセット/Identification の規則は 791-011/012 です。
- (§1.4, §2.3, §2.4) ネットワーク間のデータグラムのルーティングとゲートウェイによる転送、および Gateway to Gateway Protocol。ルーターやゲートウェイの動作で、エンドポイントの関心事ではありません。
- (§3.1 Type of Service) Type of Service フィールドの優先度、遅延、スループット、信頼性の指示。途中のネットワークの選択へのヒントで、エンドポイントである wired はこれに応じて動きません。このフィールドは `ipv4_build` がゼロにしており、「この 3 つの指示のうち設定するのは多くとも 2 つにするべきである」も満たします。
- (§3.3 Interfaces) IP とその利用者の間の上位インターフェースの SEND/RECV の例(SEND に失敗したときのエラー報告と、未知の利用者に対する ICMP エラーを含む)。説明のための API の形です。ICMP(RFC 792)は提供していません。
- (§2.3 Addressing) インターネットアドレスとローカルネットワークのアドレスの対応づけと、マルチホームのホスト。OS や運用者のアドレス設定です。
- (§3.2 Fragmentation) 断片のデータを 8 オクテット境界で分けることと、68 オクテットのデータグラムを断片化せずに転送すること。断片化や転送を行うモジュールの動作で、wired は断片化も転送もしません。
- (付録 A, 付録 B) 計算例と、データ送信のビット順。説明のためのもので、RFC 1071 の台帳にあるチェックサムの計算例にすでに反映しています。
- (Glossary, References) 用語の定義と参考文献。規範ではありません。
