# BIP-340: secp256k1 上の Schnorr 署名

仕様の本文(<https://github.com/bitcoin/bips/blob/master/bip-0340.mediawiki>)から抽出した EARS 形式の要件台帳です。各要件には、それを確かめるテストを付けています。チェックがなくテスト行もない項目は、未解決のギャップです。

wired が実装するのは検証だけです。入力はすべて公開の値なので、実装は可変時間で動きます。今は NIP-01 のイベントの検証(`nostrev_verify`)と NIP-98 の検査(`nip98_check`)だけが呼び、サーバーの本番の経路からはまだ呼ばれません。そのため項目は `[~]` にしています。

凡例:

- `[x]`: 挙げたテストで確認済み
- `[~]`: 間接的に確認(専用のテストはなく、evidence 行で確かめ方を説明)
- `[ ]`: まだどのテストでも確認していない

**カバレッジ: テスト済み 0/12、間接 12、未テスト 0。**

## Design / Specification

- [~] B340-001 (Specification) 実装は、SEC 2 の secp256k1(p = 2^256 - 2^32 - 977、位数 n、生成元 G)の上で署名を検証しなければならない。
  - evidence: `tests/crypto/secp256k1_test.c` の `test_secp256k1_constants`(Montgomery 定数を p から計算し直す)、`test_secp256k1_lift_g`(G が曲線上にある)、`test_secp256k1_mul2`(n*G が無限遠点、(n-1)*G = -G)が確かめる。サーバーからはまだ呼ばれない。
- [~] B340-002 (Specification) lift_x では、x >= p のとき、実装は失敗しなければならない。
  - evidence: `tests/crypto/secp256k1_test.c` の `test_secp256k1_lift_reject` が x = p と全ビット 1 を確かめる。サーバーからはまだ呼ばれない。
- [~] B340-003 (Specification) lift_x では、実装は c = x^3 + 7、y = c^((p+1)/4) を計算し、c ≠ y^2 のとき失敗しなければならない。
  - evidence: `tests/crypto/secp256k1_test.c` の `test_secp256k1_lift_reject` が、曲線上にない x(test-vectors.csv の 5 行目の公開鍵)を確かめる。サーバーからはまだ呼ばれない。
- [~] B340-004 (Specification) lift_x では、実装は y が偶数の点を返さなければならない。
  - evidence: `tests/crypto/secp256k1_test.c` の `test_secp256k1_lift_even` が 2G と 3G の x で確かめる。サーバーからはまだ呼ばれない。

## Verification

- [~] B340-005 (Verification) 公開鍵の lift_x が失敗するとき、実装は検証を失敗させなければならない。
  - evidence: `tests/crypto/bip340_test.c` の `test_bip340_csv` が test-vectors.csv の 5 行目と 14 行目を確かめる。サーバーからはまだ呼ばれない。
- [~] B340-006 (Verification) r >= p のとき、実装は検証を失敗させなければならない。
  - evidence: `tests/crypto/bip340_test.c` の `test_bip340_csv` が 12 行目を確かめる。サーバーからはまだ呼ばれない。
- [~] B340-007 (Verification) s >= n のとき、実装は検証を失敗させなければならない。
  - evidence: `tests/crypto/bip340_test.c` の `test_bip340_csv` が 13 行目を確かめる。サーバーからはまだ呼ばれない。
- [~] B340-008 (Verification) 実装は、e = int(hash_BIP0340/challenge(bytes(r) || bytes(P) || m)) mod n を、タグ付きハッシュ SHA256(SHA256(tag) || SHA256(tag) || x) で計算しなければならない。
  - evidence: `tests/crypto/bip340_test.c` の `test_bip340_csv` の有効な行(0〜4、15〜18)が、この e でしか通らない。サーバーからはまだ呼ばれない。
- [~] B340-009 (Verification) R = s*G - e*P が無限遠点のとき、実装は検証を失敗させなければならない。
  - evidence: `tests/crypto/bip340_test.c` の `test_bip340_csv` が 10 行目と 11 行目を確かめる。サーバーからはまだ呼ばれない。
- [~] B340-010 (Verification) y(R) が奇数のとき、実装は検証を失敗させなければならない。
  - evidence: `tests/crypto/bip340_test.c` の `test_bip340_csv` が 6 行目を確かめる。サーバーからはまだ呼ばれない。
- [~] B340-011 (Verification) x(R) ≠ r のとき、実装は検証を失敗させなければならない。
  - evidence: `tests/crypto/bip340_test.c` の `test_bip340_csv` が 7〜9 行目を、`test_bip340_tamper` が r、s、メッセージの 1 ビットの反転を確かめる。サーバーからはまだ呼ばれない。
- [~] B340-012 (Verification) 実装は、任意の長さのメッセージを検証しなければならない。
  - evidence: `tests/crypto/bip340_test.c` の `test_bip340_csv` が 15〜18 行目(0、1、17、100 バイト)を確かめる。サーバーからはまだ呼ばれない。

## 対象外

- (Default Signing) 署名の生成: wired は Nostr の署名を検証するだけで、秘密鍵を持たない。署名側のテストベクター(秘密鍵のある行)は検証の向きだけで確かめる。
- (Batch Verification) 一括検証: 検証は 1 件ずつ行う。
- (Public Key Generation) 鍵の生成: 署名を作らないので要らない。
