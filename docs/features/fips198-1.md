# FIPS 198-1: 鍵付きハッシュメッセージ認証コード（HMAC）

仕様の本文(`tasks/specs/fips198-1.txt`。git には含まない)から抽出した EARS 形式の要件台帳です。対象は SDK が提供する HMAC-SHA-256、HMAC-SHA-384 の 2 つのインスタンスに絞っています(`src/crypto/symmetric/hash/hash/hmac.c`。B = 64/128、L = 32/48)。各要件には、それを確かめるテストを付けています。チェックがなくテスト行もない項目は、未解決のギャップです。

凡例:

- `[x]`: 挙げたテストで確認済み
- `[~]`: 間接的に確認(専用のテストはなく、evidence 行で確かめ方を説明)
- `[ ]`: まだどのテストでも確認していない

**カバレッジ: テスト済み 9/10、間接 1、未テスト 0。**

## §1 はじめに

- [x] F198-009 (§1, Announcement 9) 実装は、H として承認されたハッシュ関数(SHA-256、SHA-384、SHA-512 のいずれか)を使わなければならない。
  - test: `tests/crypto/hmac_test.c` — `test_hmac_vectors`
  - test: `tests/crypto/hmac_test.c` — `test_hmac384_vectors`

## §2.3 HMAC のパラメーターおよび記号

- [~] F198-010 (§2.3) 実装は、0 <= n < 2^B - 8B ビットを満たす任意の長さ n の text を受け付けなければならない。
  - evidence: `hmac_sha256/384` は任意の長さのバイト列 `wired_span` を受け取り、そのままハッシュに通します。空の鍵と短い入力は `test_bssl_hmac` で通していますが、上限に近い長さを試すテストはありません。

## §3 暗号鍵

- [x] F198-001 (§3) 鍵 K がハッシュ関数のブロックサイズ B より長いとき、実装はまず H で K をハッシュし、得られた L バイトの文字列を K0 として使わなければならない。
  - test: `tests/crypto/hmac_test.c` — `test_hmac_long_key`
  - test: `tests/crypto/hmac_test.c` — `test_hmac384_long_key`

## §4 HMAC の仕様

- [x] F198-002 (§4) 実装は MAC(text) = H((K0 XOR opad) || H((K0 XOR ipad) || text)) を計算しなければならない。ここで ipad はバイト x'36' を B 回繰り返したもの、opad はバイト x'5c' を B 回繰り返したものである。
  - test: `tests/crypto/hmac_test.c` — `test_hmac_vectors`
  - test: `tests/crypto/hmac_test.c` — `test_hmac_long_key`
  - test: `tests/crypto/bssl_hmac_test.c` — `test_bssl_hmac`
- [x] F198-003 (§4 Step 1) K の長さが B に等しい場合、実装は K0 = K とそのまま設定しなければならない。
  - test: `tests/crypto/bssl_hmac_test.c` — `test_bssl_hmac`
    (NIST の "keylen=blocklen" のケース。SHA-256 は 64 バイトの鍵、
    SHA-384 は 128 バイトの鍵)
- [x] F198-004 (§4 Step 2) K の長さが B より大きい場合、実装は K0 を H(K) の後ろに (B-L) 個のゼロバイトを続けたものに設定しなければならない。
  - test: `tests/crypto/hmac_test.c` — `test_hmac_long_key`
  - test: `tests/crypto/hmac_test.c` — `test_hmac384_long_key`
- [x] F198-005 (§4 Step 3) K の長さが B より小さい場合、実装は K の末尾にゼロバイトを付加して B バイトの文字列 K0 を作らなければならない。
  - test: `tests/crypto/hmac_test.c` — `test_hmac_vectors`
- [x] F198-006 (§4 Steps 4-6) 実装は、K0 と ipad の排他的論理和をとり、text を付加し、その結果に H を適用して内側のハッシュ H((K0 XOR ipad) || text) を計算しなければならない。
  - test: `tests/crypto/hmac_test.c` — `test_hmac_vectors`
- [x] F198-007 (§4 Steps 7-9) 実装は、K0 と opad の排他的論理和をとり、内側のハッシュの結果を付加し、もう一度 H を適用して最終的な MAC を計算しなければならない。
  - test: `tests/crypto/hmac_test.c` — `test_hmac_vectors`

## §5 切り詰め

- [x] F198-008 (§5) アプリケーションが HMAC の出力を切り詰める構成では、実装は HMAC の出力の左端 lambda ビットを MAC として使わなければならない。
  - test: `tests/crypto/wyc_hmac_sha256_test.c` — `test_wyc_hmac_sha256`

## 対象外

このサーバー SDK が実装しない、クライアント専用または運用者側の要件です。カバレッジの分母から除いています。

- (§1) はじめに。参考情報。
- (§2) 用語と略語の解説、パラメーターと記号の定義。参考情報。
- (§3) 鍵のセキュリティ強度と鍵管理(SP 800-57)の指針のうち、すでに取り込んだ K > B の事前ハッシュの規則(F198-001)を超える部分。運用者の関心事。
- (§6) (K0 XOR ipad)/(K0 XOR opad) に対する圧縮関数の中間結果を事前計算してキャッシュする実装上の注意。相互接続性に影響しないと明記された性能の最適化です。SDK は呼び出しのたびに両方のパッドを計算し直すので、保存した中間値を「秘密鍵と同じように取り扱い、保護しなければならない」という規則は当てはまる対象がありません。
- (§6) 実行時に下位の承認されたハッシュ関数 H を差し替えること。SDK は固定の 3 つのインスタンス(HMAC-SHA-256/384/512)を提供し、それぞれが B の大きさに合わせた固有のパッドを持ちます。実行時にハッシュ関数を切り替える仕組みはありません。
- (Announcement 8, 12) HMAC の鍵は「ほかの目的に使うべきではない」、「利用者はこれらの鍵の漏えいを防がなければならない」。鍵管理は呼び出し側のプロトコル(TLS 1.3 の鍵スケジュール)の責務です。
- (Announcement 9, 10, 12) 承認された鍵の生成と管理、輸出規制、政府機関のセキュリティ責任。方針の記述。
- (Appendix A) FIPS 198 と FIPS 198-1 の違い。経緯の説明で、現在の要件ではありません。
- (Appendix B) 参考文献。参考情報。
