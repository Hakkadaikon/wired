## §3.1 アプリケーション層プロトコルネゴシエーション拡張

- [x] 7301-001 (§3.1) サーバーは ClientHello の "application_layer_protocol_negotiation(16)" 拡張を解析しなければならない。その extension_data は ProtocolNameList で、2 バイトのリスト長のあとに、1 バイトの長さを前に付けたプロトコル名が 1 つ以上続く。

  - test: `tests/tls/salpn_raw_test.c` — `test_salpn_raw_pick_client_order`
  - test: `tests/tls/negotiate_test.c` —
    `test_negotiate_selects_h3_from_clienthello`
- [x] 7301-002 (§3.1) サーバーは ClientHello の拡張ブロックの中から、型(extension_type 0x0010)で ALPN 拡張を見つけなければならない。
  - test: `tests/tls/ch_ext_test.c` — `test_ch_ext_finds_alpn_and_sni`
- [x] 7301-003 (§3.1) サーバーは自分が送る ProtocolNameList に、空のプロトコル名や途中で切れたプロトコル名を含めてはならない。
  - test: `tests/tls/salpn_raw_test.c` — `test_salpn_raw_ee_bytes`
  - test: `tests/tls/alpn_test.c` — `test_alpn_encode_guard`
- [x] 7301-004 (§3.1, §3.2) ClientHello が ALPN 拡張を持つとき、サーバーは認識できないプロトコル名をすべて無視し、クライアントが広告したプロトコルの中からだけ選ばなければならない。
  - test: `tests/tls/salpn_raw_test.c` — `test_salpn_raw_pick_client_order`
  - test: `tests/tls/negotiate_test.c` — `test_negotiate_rejects_non_h3`
  - test: `tests/tls/negotiate_test.c` — `test_negotiate_h3_among_others`
- [x] 7301-005 (§3.1) サーバーが ALPN 拡張を返すとき(TLS 1.3 では EncryptedExtensions の中)、その ProtocolNameList はちょうど 1 つの ProtocolName を含まなければならない。
  - test: `tests/tls/salpn_raw_test.c` — `test_salpn_raw_ee_bytes`
  - test: `tests/tls/eebuild_test.c` — `test_eebuild`
- [~] 7301-006 (§3.1) セッションを再開するとき、サーバーは以前のセッションの値ではなく、新しいハンドシェイクの ALPN 拡張だけから ALPN をネゴシエートしなければならない。
  - evidence: サーバーの ALPN ネゴシエーション(`src/tls/handshake/core/sdrv/sdrv_psk.c` の `sdrv_negotiate_alpn`)は、再開のハンドシェイクも含め、ClientHello ごとにその ClientHello 自身の ALPN 拡張から `s->alpn` を無条件にリセットして導出し直す。以前のセッションの ALPN の選択を再利用するコード経路はない。再開と ALPN を組み合わせた専用のテストはない。
- [x] 7301-015 (§3.1) サーバーは空の ProtocolName を決して選んではならず、2 オクテットの最小長に満たないリストからは何も選んではならない。
  - test: `tests/tls/salpn_raw_test.c` — `test_salpn_raw_pick_malformed`

## §3.2 プロトコルの選択

- [x] 7301-007 (§3.2) サーバーは自分がサポートし、かつクライアントも広告したプロトコルの中から、自分が最も優先するものを選ぶべきである。
  - test: `tests/tls/sni_srv_test.c` — `test_snisrv_alpn_server_preference`
  - test: `tests/tls/salpn_raw_test.c` — `test_salpn_raw_pick_server_order`,
    `test_salpn_raw_pick_server_malformed`
  - `sdrv_negotiate_alpn` は `salpn_raw_pick_server` を使う(設定した raw の ID を順に、次に h3、次に hq-interop)。interop のイメージは `--alpn-client-order`(`wired_srvboot_id.alpn_client_order`)を渡して、msquic のクライアント順の振る舞いを保つ(`test_negotiate_follows_client_order`)。
- [x] 7301-008 (§3.2) クライアントが広告したプロトコルをどれもサポートしていない場合、サーバーは致命的な "no_application_protocol"(120)アラートで応答しなければならない。
  - test: `tests/tls/sdrv_test.c` — `test_sdrv_no_alpn_match_is_0x178`
  - test: `tests/tls/salpn_raw_test.c` — `test_salpn_raw_srvboot`
  - test: `tests/tls/negotiate_test.c` —
    `test_negotiate_none_when_neither_offered`
  - vuln: V-0293
- [~] 7301-009 (§3.2) サーバーの ALPN 拡張で示したプロトコルは、その接続に対して確定したものでなければならず、サーバーは選んだプロトコルで応答しておきながら、その後に別のプロトコルを使ってはならない。
  - evidence: `s->alpn` は `sdrv_negotiate_alpn` が一度だけ決め、`eebuild_encrypted_extensions` が EncryptedExtensions に返すのも同じ値である。QUIC には再ネゴシエーションがない(RFC 9001)ので、「再ネゴシエーションされるまで」は自明に成り立つ。`test_eebuild_rejects_no_negotiation` が示すのは fail-closed の分岐(ネゴシエートしていなければ拒否する分岐)だけで、返した ID とその後に話すプロトコルを結びつけるテストはない。

## 対象外

クライアント側の記述、説明のための記述、レジストリの方針の記述です。カバレッジの分母には含めません。

- (§3.1) ClientHello に ALPN 拡張を含めること。クライアントの振る舞い。
- (§3.1) 図 1-2 の TLS 1.2 のフルハンドシェイクと短縮ハンドシェイクの流れ。QUIC は TLS 1.3 で動き、サーバーの ALPN は EncryptedExtensions に入る。
- (§4) 平文の ServerHello についての注記を含む設計上の考慮事項。説明のための記述であり、TLS 1.3 は EncryptedExtensions を暗号化する。
- (§5) プライバシーに関わる識別子を、平文で見える場所で使わないこと、およびその仕様の中で使わないよう勧めること。レジストリと運用者への指針。
- (§6) IANA のレジストリの手続きと初期登録。レジストリの方針。上で使うのはバイト単位で完全一致させる Identification Sequence だけ。
