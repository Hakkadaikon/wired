# RFC 7301 — TLS Application-Layer Protocol Negotiation (ALPN)

EARS requirement ledger extracted from the spec text
(`tasks/specs/rfc7301.txt`, not in git). Each requirement carries the test
that demonstrates it; an unchecked box with no test line is an open gap.
This ledger is scoped to the server side of ALPN, matching wired's role.
Status as of 2026-10.

Legend:

- `[x]` — demonstrated by the referenced test
- `[~]` — exercised indirectly (evidence line explains how; no dedicated test)
- `[ ]` — not demonstrated by any test yet

**Coverage: 12/15 tested, 2 indirect, 1 untested.**

## §3.1 The Application-Layer Protocol Negotiation Extension

- [x] 7301-001 (§3.1) The server shall parse a ClientHello
  "application_layer_protocol_negotiation(16)" extension whose
  extension_data is a ProtocolNameList: a 2-byte list length followed by
  one or more 1-byte-length-prefixed protocol names.
  - test: `tests/tls/salpn_raw_test.c` — `test_salpn_raw_srvboot`
  - test: `tests/tls/salpn_raw_test.c` — `test_salpn_raw_pick_client_order`
  - test: `tests/tls/negotiate_test.c` —
    `test_negotiate_selects_h3_from_clienthello`
- [x] 7301-002 (§3.1) The server shall locate the ALPN extension
  (extension_type 0x0010) inside a ClientHello's extensions block by its
  type.
  - test: `tests/tls/ch_ext_test.c` — `test_ch_ext_finds_alpn_and_sni`
- [x] 7301-003 (§3.1) The server shall not include an empty or truncated
  protocol name in a ProtocolNameList it sends.
  - test: `tests/tls/salpn_raw_test.c` — `test_salpn_raw_ee_bytes`
  - test: `tests/tls/alpn_test.c` — `test_alpn_encode_guard`
- [x] 7301-004 (§3.1, §3.2) When a ClientHello carries the ALPN extension,
  the server shall ignore every protocol name it does not recognize and
  select only a protocol the client advertised.
  - test: `tests/tls/salpn_raw_test.c` — `test_salpn_raw_pick_client_order`
  - test: `tests/tls/negotiate_test.c` — `test_negotiate_rejects_non_h3`
  - test: `tests/tls/negotiate_test.c` — `test_negotiate_h3_among_others`
- [x] 7301-005 (§3.1) When the server returns an ALPN extension (in
  EncryptedExtensions for TLS 1.3), its ProtocolNameList shall contain
  exactly one ProtocolName.
  - test: `tests/tls/salpn_raw_test.c` — `test_salpn_raw_ee_bytes`
  - test: `tests/tls/eebuild_test.c` — `test_eebuild`
- [~] 7301-006 (§3.1) When a session is resumed, the server shall
  negotiate ALPN from the new handshake's ALPN extension only, not from
  the previous session's value.
  - evidence: the server's ALPN negotiation (`sdrv_negotiate_alpn` in
    `src/tls/handshake/core/sdrv/sdrv_psk.c`) resets and re-derives
    `s->alpn` from each ClientHello's own ALPN extension unconditionally,
    including on a resumption handshake; there is no code path that
    reuses a prior session's ALPN choice — no dedicated resumption+ALPN
    test.
- [x] 7301-015 (§3.1) The server shall never select an empty ProtocolName,
  and shall select nothing from a list shorter than its 2-octet minimum.
  - test: `tests/tls/salpn_raw_test.c` — `test_salpn_raw_pick_malformed`

## §3.2 Protocol Selection

- [ ] 7301-007 (§3.2) The server should select its own most highly
  preferred protocol among those it supports that the client also
  advertised.
  - gap: `salpn_raw_pick` deliberately walks the client's list in the
    client's order and takes the first protocol it speaks (pinned by
    `test_negotiate_follows_client_order` against msquic's captured
    offer); the server applies no preference order of its own.
- [x] 7301-008 (§3.2) If the server supports none of the protocols the
  client advertises, then the server shall respond with a fatal
  "no_application_protocol" (120) alert.
  - test: `tests/tls/sdrv_test.c` — `test_sdrv_no_alpn_match_is_0x178`
  - test: `tests/tls/salpn_raw_test.c` — `test_salpn_raw_srvboot`
  - test: `tests/tls/negotiate_test.c` —
    `test_negotiate_none_when_neither_offered`
- [~] 7301-009 (§3.2) The protocol identified in the server's ALPN
  extension shall be definitive for the connection; the server shall not
  respond with a selected protocol and subsequently use a different one.
  - evidence: `s->alpn` is decided once by `sdrv_negotiate_alpn` and the
    same value is what `eebuild_encrypted_extensions` echoes into
    EncryptedExtensions; QUIC has no renegotiation (RFC 9001), so "until
    renegotiated" is vacuously true. `test_eebuild_rejects_no_negotiation`
    shows only the fail-closed branch — no test ties the echoed id to the
    protocol then spoken.

## Protocol name registry (§6 IANA Considerations)

- [x] 7301-010 (§6) The server shall match the "h3" protocol identifier
  (its ALPN choice for HTTP/3, RFC 9114) by exact byte comparison
  (0x68 0x33).
  - test: `tests/tls/alpn_match_test.c` — `test_alpn_match_is_h3`
- [x] 7301-011 (§3.1, §6) The server shall compare protocol names exactly
  and length-sensitively: a name that is a prefix, an extension or a case
  variant of a supported identifier shall not match.
  - test: `tests/tls/alpn_match_test.c` — `test_alpn_match_is_h3`
  - test: `tests/tls/alpn_match_test.c` — `test_alpn_match_equal`
  - test: `tests/tls/salpn_raw_test.c` — `test_salpn_raw_list_has`

## Wire-format robustness (implicit in §3.1's ProtocolNameList grammar)

- [x] 7301-012 (§3.1) If an ALPN extension's list-length or name-length
  field overruns the available bytes, then the server shall reject it
  rather than over-read.
  - test: `tests/tls/salpn_raw_test.c` — `test_salpn_raw_pick_malformed`
  - test: `tests/tls/salpn_raw_test.c` — `test_salpn_raw_pick_truncations`
  - test: `tests/tls/ch_ext_test.c` — `test_ch_ext_truncated_returns_zero`
  - test: `fuzz/fuzz_tlsmsg.c` — `fuzz_ch_extensions`
- [x] 7301-013 (§3.1) The server shall encode a ProtocolNameList entry only
  when it fits the destination buffer and the protocol name is non-empty
  and at most 255 octets.
  - test: `tests/tls/salpn_raw_test.c` — `test_salpn_raw_ee_bytes`
  - test: `tests/tls/alpn_test.c` — `test_alpn_encode_guard`
- [x] 7301-014 (§3.1, §3.2) The server shall build the EncryptedExtensions
  ALPN response with the one negotiated protocol ("h3" or "hq-interop",
  the interop runner's HTTP/0.9-over-QUIC id) and shall build nothing
  when no protocol was negotiated.
  - test: `tests/tls/eebuild_test.c` — `test_eebuild_selects_hq`
  - test: `tests/tls/eebuild_test.c` — `test_eebuild_rejects_no_negotiation`

## Out of scope

Client-side, descriptive or registry-policy text, excluded from the
coverage denominator:

- (§3.1) Including the ALPN extension in the ClientHello — client
  behavior.
- (§3.1) Figures 1-2, the TLS 1.2 full and abbreviated handshake flows —
  QUIC runs TLS 1.3, where the server's ALPN goes in EncryptedExtensions.
- (§4) Design considerations, including the plaintext ServerHello note —
  descriptive; TLS 1.3 encrypts EncryptedExtensions.
- (§5) Not using privacy-sensitive identifiers where they are visible in
  the clear, and recommending against it in their specifications —
  registry and operator guidance.
- (§6) IANA registry procedure and initial registrations — registry
  policy; only the byte-exact Identification Sequence is used above.
