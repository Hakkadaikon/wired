## 対象外

このサーバー SDK が実装しないアルゴリズムと、CA が生成するときの方針です。カバレッジの分母には含めません。

- 5758-001 (§2) id-sha224 の OBJECT IDENTIFIER を単独で認識すること(ダイジェストアルゴリズム単体のこと。5758-007 がすでに扱う複合の ecdsa-with-SHA224 signatureAlgorithm OID ではない)。証明書の signatureAlgorithm フィールドには複合の形しか現れないため、この SDK の呼び出し側が単独のダイジェスト OID を解決する必要はない。下の 5758-006 の DSA と同じく、認識しても使い道のない OID という判断。
- 5758-005 (§2) 単独の SHA-2 ハッシュの AlgorithmIdentifier で、パラメーターが NULL の場合と省略された場合の両方を受け入れること。この SDK が読む単独のハッシュ OID は PKCS#1 v1.5 の DigestInfo だけで、そこでは RFC 8017 Appendix B.1 の例外がパラメーターを NULL に固定している(`rsa_pkcs1_verify` はその形と比較する)。ほかのハッシュの AlgorithmIdentifier は解析しない。
- 5758-006 (§3.1) id-dsa-with-sha224/id-dsa-with-sha256 を DSA 署名アルゴリズムとして認識すること。SDK が実装する署名の検証と生成は RSA-PKCS1 と ECDSA だけで、`src/crypto/` のどこにも DSA のコード経路はない。OID を認識するだけでは使い道がない。認識した OID の振り分け先となる `X509_SIG_DSA` の鍵の種類も、DSA の検証プリミティブもないためである。
- (§3.1, §3.2) FIPS 186-4 への適合を求める生成の要件("Conforming CA implementations ... MUST generate ... in accordance with all the requirements in Sections 4.1, 4.5, and 4.6 of [FIPS186-3]")。CA の運用方針の記述であり、このサーバー SDK のワイヤーフォーマットや解析の振る舞いとしてテストできるものではない。
- (§5) 鍵長の選び方について NIST SP 800-56A/57/107 と X9.62 を示すセキュリティ上の考慮事項の指針。運用者向けの方針の指針であり、コードの振る舞いとして実装できるものではない。
