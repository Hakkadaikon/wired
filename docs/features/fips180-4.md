# FIPS 180-4: セキュアハッシュ標準（SHS）

仕様の本文(`tasks/specs/fips180-4.txt`。git には含まない)から抽出した EARS 形式の要件台帳です。対象は SDK が提供するハッシュ関数に絞っています。SHA-256(`src/crypto/symmetric/hash/hash/sha256.c`)と、SHA-512 の圧縮関数を共有する SHA-384 と SHA-512(`sha384.c`/`sha512.c`)です。SHA-1、SHA-224、SHA-512/224、SHA-512/256 は提供していません。各要件には、それを確かめるテストを付けています。チェックがなくテスト行もない項目は、未解決のギャップです。2026-10 時点の状況です。

凡例:

- `[x]`: 挙げたテストで確認済み
- `[~]`: 間接的に確認(専用のテストはなく、evidence 行で確かめ方を説明)
- `[ ]`: まだどのテストでも確認していない

**カバレッジ: テスト済み 24/26、間接 2、未テスト 0。**

## §1 メッセージの長さ

- [~] F180-026 (§1, §2.2 Figure 1) 実装は、2^64 ビット未満(SHA-256)または 2^128 ビット未満(SHA-384、SHA-512)の任意のメッセージをハッシュしなければならない。
  - evidence: `sha256_ctx`/`sha512_ctx`(`src/crypto/symmetric/hash/hash/`)はバイト数を u64 で数えます。SHA-256 では 2^64 ビットまで届きますが、SHA-384/512 では上限が 2^67 ビットになります(2^128 よりはるかに小さいものの、実用上は到達しません)。どちらの上限に近い長さを試すテストもありません。

## §7 メッセージダイジェストの切り詰め

- [~] F180-025 (§7) アプリケーションがどのハッシュ関数の本来の出力とも異なる長さのメッセージダイジェストを必要とする構成では、実装は、より長いダイジェストの左端から必要な数のビットを選んで切り詰めなければならない。
  - evidence: 汎用の切り詰めヘルパーはありません。「長いほうのハッシュを計算して切り詰める」例として提供しているのは SHA-384 だけです(F180-024)。`test_sha384_is_sha512_truncation`(`tests/crypto/sha384_test.c`)は SHA-384 が SHA-512 をちょうど切り詰めたものであることを確かめており、これが別の汎用の操作ではなく唯一の切り詰めの経路であることを裏づけています。
