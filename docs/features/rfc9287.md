# RFC 9287 — Greasing the QUIC Bit

EARS requirement ledger extracted from the spec text
(`tasks/specs/rfc9287.txt`, not in git). Each requirement carries the test
that demonstrates it; an unchecked box with no test line is an open gap.
Status as of 2026-10.

Legend:

- `[x]` — demonstrated by the referenced test
- `[~]` — exercised indirectly (evidence line explains how; no dedicated test)
- `[ ]` — not demonstrated by any test yet

**Coverage: 7/8 tested, 1 indirect, 0 untested.**

## §3 The Grease QUIC Bit Transport Parameter

- [x] 9287-001 (§3) Where greasing is enabled, the server shall send the
  grease_quic_bit transport parameter (0x2ab2) with an empty value.
  - test: `tests/tls/server_tp_test.c` — `test_server_tp_grease_quic_bit`
    (`stp_build_server_ret`, the server flight's TP builder, emits it via
    `grease_encode`)
- [x] 9287-002 (§3) Where the server understands the grease_quic_bit
  transport parameter, if one is received with a non-empty value, then the
  server shall treat it as a connection error of type
  TRANSPORT_PARAMETER_ERROR.
  - test: `tests/tls/sdrv_test.c` —
    `test_sdrv_recv_client_hello_grease_quic_bit`
- [x] 9287-003 (§3) While the server advertises the grease_quic_bit
  transport parameter, the server shall accept packets with the QUIC Bit
  (0x40) set to 0.
  - test: `tests/app/srvloop_test.c` —
    `test_srvloop_accepts_cleared_quic_bit` (no receive path tests the bit)

## §3.1 Clearing the QUIC Bit

- [x] 9287-004 (§3.1) The server shall set the QUIC Bit to 0 only when the
  peer advertised the grease_quic_bit transport parameter.
  - test: `tests/app/srvloop_test.c` — `test_srvloop_send_greases_quic_bit`
    (64 packets without the client's parameter all keep the bit;
    `greasebit_may_clear` gates `send_onertt_clear_bit`). Long-header
    builders always set 0x40.
- [x] 9287-005 (§3.1) When the peer advertised grease_quic_bit, the server
  should set the QUIC Bit to an unpredictable value.
  - test: `tests/app/srvloop_test.c` — `test_srvloop_send_greases_quic_bit`
    (both values occur; the bit is drawn from a per-connection random seed
    mixed with the packet number)
- [x] 9287-006 (§3.1) The server shall set the QUIC Bit to 0 only after
  processing the client's transport parameters and advertising
  grease_quic_bit itself.
  - test: `tests/tls/sdrv_test.c` —
    `test_sdrv_recv_client_hello_grease_quic_bit` (the permission is only
    ever set from the ClientHello's TPs) with
    `test_srvloop_send_greases_quic_bit`; only 1-RTT packets, sent after
    the flight that advertises it, are greased.
- [~] 9287-007 (§3.1) The server shall not set the QUIC Bit to 0 based on a
  remembered negotiation from a previous connection.
  - evidence: structural -- `peer_grease_quic_bit` lives in the
    per-connection `sdrv` and is reset by `sdrv_init`; tickets carry no
    grease state; no test.
- [x] 9287-009 (§3.1) The server shall not set the QUIC Bit to 0 on any
  packet, including a Stateless Reset, without knowing that the peer
  supports the extension.
  - test: `tests/transport/sreset_test.c` — `test_sreset_build_fixed_bits`
    (`sreset_build` forces the first bits to 0b01 over any RNG output)

## Out of scope

Requirements on parties or features this server SDK does not implement,
excluded from the coverage denominator:

- (§3.1) A client clearing the QUIC Bit before receiving the server's
  transport parameters, and its NEW_TOKEN / 7-day precondition — client
  behavior.
- (§3.2) Extensions that assign semantics to the QUIC Bit and their
  negotiation rules — no such extension is shipped.
- (§4) The effect of greasing on network operators' traffic classification
  — operator consideration, no SDK code.
