# ドキュメント規約

[ドキュメント](../README.md) › [開発標準](README.md) › ドキュメント規約

| 項目 | 内容 |
|---|---|
| 目的 | README.md と docs/ の文書の構成と書き方を定める |
| 読む人 | 文書を書く・直すコントリビューター |
| 前提文書 | [ユビキタス言語](../ubiquitous/README.md) |
| 関連文書 | [開発標準](README.md) |

## 1. 対象

| 対象 | 扱い |
|---|---|
| README.md、docs/ | この規約に従う |
| docs/features/ の RFC・FIPS・SP・ドラフトの台帳 | 外部の訳を元にするので対象外 |
| docs/superpowers/ | 過去の設計と計画の記録。この規約に従うが、記録として決定・手順・チェックボックスの中身は変えない |
| docs/sdk/ | doxygen の生成物で、対象外 |
| guide/ | 利用者向けの解説。この規約の対象外(文体は です・ます) |

## 2. 読み手と置き場所

docs/ はコントリビューター向けである。アプリケーションを作る利用者向けの説明は guide/ に置く。guide/ は日本語と英語の両方のページを持ち、英語のページは消さない。

| 内容 | 置き場所 |
|---|---|
| 利用者がする操作と API の使い方 | guide/(ja と en) |
| 仕組み、設計の理由、変更の手順、検証の結果 | docs/ |

## 3. 文書の構成

### 3.1 文書体系

| ディレクトリ | 文書の種類 | 中身 |
|---|---|---|
| `overview/` | 概要書 | 目的、適用範囲、設計方針 |
| `architecture/` | 基本設計書 | 全体構成、データの流れ、I/O、メモリ、鍵 |
| `design/` | 詳細設計書 | ドメインごとの設計、実装している仕様 |
| `standards/` | 開発標準 | 規約、ビルド、ゲート、手順 |
| `reference/` | 参照資料 | API の区分、システムコール |
| `verification/` | 試験と品質 | テストの範囲、相互運用性テスト、性能 |
| `security/` | セキュリティ設計 | 脅威モデル、検査、既知の制限、脆弱性台帳 |
| `features/` | 要件台帳 | 仕様ごとの要件と、それを確かめるテスト |
| `ubiquitous/` | 用語集 | 技術用語の表記 |

### 3.2 1 つの文書

1 文書は 1 つのテーマにし、300 行を超えたら章で分ける。冒頭は次の形にする。

```markdown
# 文書名

[ドキュメント](../README.md) › [ディレクトリの文書](README.md) › 文書名

| 項目 | 内容 |
|---|---|
| 目的 | 1 行 |
| 読む人 | 1 行 |
| 前提文書 | 先に読む文書 |
| 関連文書 | 一緒に見る文書 |
```

見出しには章番号を付ける(`## 1. 〜`、`### 1.1 〜`)。ディレクトリ名には番号を付けない。

## 4. 書き方

| 規則 | 内容 |
|---|---|
| 文体 | である調。文末は「〜する」「〜である」「〜ない」。「〜だ」「〜してください」は使わない |
| 事実 | 事実、数値、出典だけを書く。評価の語と比喩(速い、小さい、安全、きれい)は書かない。比較は数値の表で示す |
| 文の長さ | 1 文は 50 字を目安にする |
| 段落 | 1 段落 1 話題、3 文まで |
| 表と図を先に | 比べるものは表、順序と流れと状態は図、手順は番号付きの箇条にする。図や表で言えることを本文で繰り返さない |
| 同じ説明は 1 か所 | 理由や仕組みの説明は、それを扱う文書 1 か所にだけ書き、ほかからはリンクする |
| 用語の解説 | 一般的な用語(MECE、CCN、EARS、use-after-free など)は解説しない。プロジェクト独自の語だけ、初出で 1 行添える |
| 前置きとつなぎ | 「このページは〜」の前置き、「次へ」のつなぎ、本文の繰り返しになるまとめは書かない |
| 技術用語 | [ユビキタス言語](../ubiquitous/README.md) に従う。載っていない語で迷ったら英語のまま書く |

## 5. 図

- mermaid で描き、ラベルは英語にする。
- 1 つの図に 1 つのことだけを描く(依存、流れ、状態、判定)。
- 図の後の本文は、図にない補足だけを 3 行までにする。

## 6. リンク

文書を移したり分けたりしても、外部からのリンクを切らない。

| 変更 | 対応 |
|---|---|
| 文書を移す・分ける | 元のパスに移転先の表だけのページを残す |
| 見出しの名前が変わる | 古いアンカーを `<a id="…"></a>` で残す。英語版のころのアンカーも残す |
| 機械が読むパス(`docs/features/`、`docs/security/vuln-ledger.md`、`docs/syscalls.md`) | 変えない |

移転先の表だけのページは次の形にする。

```markdown
# 旧文書名(移転しました)

| 旧ページの節 | 移転先 |
|---|---|
| <a id="old-english-anchor"></a><a id="旧日本語アンカー"></a>節の名前 | [新しい文書](path#anchor) |
```
