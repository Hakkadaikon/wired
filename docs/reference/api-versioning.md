## 1. 区分ごとの変更の扱い

このプロジェクトにはリリースしたバージョン番号がまだない。下の表は提案中のデフォルトで、既存の運用ではない。

| 区分 | 互換性を壊す変更 | 追加の変更 |
|---|---|---|
| Stable API | メジャーバージョンの更新まで待つ。シグネチャの変更、削除、関数が要求または約束する内容の変更を含む | マイナーバージョンの更新で出せる。新しい関数や、安全なデフォルトを持つ省略可能な新フィールド |
| Low-level / internal API | シグネチャ、呼び出し規約、前提条件がマイナーバージョンの更新で変わりうる | — |
| experimental(MoQT) | 非推奨期間なしに、どのコミットでも変わりうる | — |
| experimental(Track 切り替え) | バージョンの更新も非推奨期間もなしに、丸ごと削除されうる | — |

パッチバージョンは Stable API と Low-level / internal API のどちらでもバグ修正だけで、シグネチャを変えない。

Low-level / internal API は `wired_server_run` と examples を組み立てるためにあり、外部の呼び出し側との契約ではない。依存する前に最新のヘッダーを読む。

## 2. バージョン番号ができるまで

| 区分 | コミットの扱い |
|---|---|
| Stable API | どのコミットも変更履歴への記載が要る |
| Low-level / internal API | どのコミットも振る舞いを変えうるものとして扱う |

## 3. 名前の接頭辞と区分

テストのビルドは全ソースを 1 つの翻訳単位にまとめるので、SDK のすべての名前が 1 つの名前空間を共有する。接頭辞は想定する利用者と所有するモジュールの両方を表す。名前の付け方と衝突の避け方は [コーディング規約](../standards/coding.md) の 5 章、ルールの全文は [`.claude/rules/naming-and-unity-build.md`](../../.claude/rules/naming-and-unity-build.md) にある。

| 接頭辞 | 対象 | 安定性 |
|---|---|---|
| `wired_*` / `WIRED_*` | [Stable API](api-stable.md) の表にあるものすべてと、同梱の examples が呼ぶ低レベルのヘルパー | 1 章に従う |
| モジュールのトークン(`sdrv_*`、`h3_*`、`bn_*`、`LEVEL_*`) | モジュール間で共有する、SDK 内部の非 `static` な名前 | 約束しない |
| `static` のヘルパー | 1 つのファイルに閉じた名前。ユニティビルドで一意に保てるように名付ける | — |
