# moqt_chat の wired_server: 4.5 時間のリソース監視


[ドキュメント](../README.md) › [試験と品質](../verification/README.md) › moqt_chat のリソース監視

| 項目 | 内容 |
|---|---|
| 目的 | 実際の利用者が使い続けた 4.5 時間の、`moqt_chat` サンプルサーバーの CPU、メモリ、ネットワークの使用量を示す |
| 読む人 | 長時間の稼働でのリソースの推移を確かめるコントリビューター |
| 前提文書 | なし |
| 関連文書 | [実装の比較](comparison.md)(スループットのベンチマーク)、[examples/moqt_chat/README.md](../../examples/moqt_chat/README.md) |

| 項目 | 内容 |
|---|---|
| 対象 | `examples/moqt_chat/server/docker-compose.yml` の `wired_server` コンテナ |
| ネットワーク | `network_mode: host`(コンテナはホストのネットワークを共有し、専用の仮想インターフェースを持たない) |
| 利用 | 実際の利用者 2〜4 人が [WebTransport のセッション](https://hakkadaikon.github.io/wired/guide/ja/wt/session/)を開いたままにした |
| 期間 | 2026-09-22 01:42–06:15 JST |
| CPU | シングルプロセス・シングルスレッドで、使えるコアは最大 1 つ |

ハブがピアの表を 1 つのプロセスのメモリに持つので、このサンプルは `--workers`/`--cores` を受け付けない。この監視は容量と動作の基準値で、スループットのベンチマークではない。メモリリークや CPU 使用率の上昇のように、何時間もたってから現れる変化を見る。


## 1. 方法

| 項目 | 内容 |
|---|---|
| サンプル | およそ 10 分ごとに 30 サンプル(最初は 01:42、最後は 06:15 JST)。01:54–02:21 に 28 分の空白が 1 つある。開始と終了の近くには数秒しか離れていないサンプルがある |
| 区間 | CPU とネットワークの差分は 3 秒の区間で平均する |
| CPU | `/proc/<pid>/stat` の `utime`+`stime` の差分を、1 コアに対する百分率に正規化する |
| メモリ | `/proc/<pid>/status` の `VmRSS` |
| ネットワーク | `/sys/class/net/eth0/statistics/{rx,tx}_bytes` の差分 |
| 生データ | [`perf-monitor.csv`](perf-monitor.csv)(30 行、1 サンプル 1 行) |

ネットワークの値はホストの主インターフェースを流れたすべての通信を数え、3 秒の区間にホストが運んだほかの通信も含む。`network_mode: host` ではコンテナごとのインターフェースがないので、スループットの値は上限として扱う。


## 2. 結果

| 指標 | 最小 | 中央値 | 平均 | 最大 |
|---|---|---|---|---|
| CPU(1 コアに対する %) | 4.00 | 7.67 | 7.80 | 12.00 |
| メモリ(VmRSS、MiB) | 20.85 | 20.85 | 20.85 | 20.85 |
| 受信スループット(KB/s) | 35.2 | 57.4 | 68.0 | 187.7 |
| 送信スループット(KB/s) | 448.4 | 673.1 | 812.5 | 1474.6 |

KB/s は毎秒 1024 バイトである。中央値は上側中央値(30 個の値を並べた 16 番目)である。

- メモリは 30 サンプルすべてで 20.85 MiB で、4.5 時間のあいだ増えていない。
- CPU は 1 コアの 4〜12 % の範囲にあり、時間とともに上がらず、接続や画面共有の動きに合わせて上下した。
- コンテナの状態はどのサンプルでも `running` で、期間中にクラッシュも再起動もない。
- 送信は受信を上回る。[ハブ](https://hakkadaikon.github.io/wired/guide/ja/moqt/hub/)は共有のライブ映像、画面共有、音声を接続しているすべてのピアに配るので、送信はピアの数に応じて増え、受信はおおよそアップロードする 1 人分になる。


## 3. テストマシン

コンテナを動かしたホスト(ConoHa VPS、KVM ゲスト)の `lscpu` の出力である。

| 項目 | 値 |
|---|---|
| CPU のモデル | Intel(R) Xeon(R) Gold 6230 @ 2.10GHz |
| vCPU | 4(4 ソケット × 1 コア) |
| アーキテクチャ | x86_64、物理アドレス 46 ビット / 仮想アドレス 48 ビット |
| ハイパーバイザー | KVM(完全仮想化) |
| L1d / L1i キャッシュ | それぞれ 128 KiB(4 インスタンス) |
| L2 キャッシュ | 16 MiB(4 インスタンス) |
| L3 キャッシュ | 64 MiB(4 インスタンス) |
| NUMA ノード | 1 |
| 主な命令セット拡張 | AVX-512(F/DQ/CD/BW/VL/VNNI)、AES-NI、RDRAND/RDSEED |

ゲストからは 4 つの vCPU が 1 コアのソケット 4 つに見える。物理的な 4 ソケットのサーバーではない。CPU の脆弱性対策はパッチを当てた KVM ゲストの既定の設定で、上の数値に影響しない。
