# moqt_chat: カメラ映像、バーチャル背景、mp4 の配信

状態: 承認済みの設計(2026-11-04)。依頼は、MediaPipe のセグメンテーションと自作の WebGL コンポジターで作るバーチャル背景付きのカメラと、保存済みの mp4 を配信するフロントエンドのトグルだった。

## 意図

参加者はカメラで自分を映せる。部屋をぼかした背景や差し替えた背景で隠すこともできる。代わりに、保存済みの mp4 をルームに配信することもできる。どちらもフロントエンドからオンとオフを切り替える。依頼では背景の方法も指定されていた。MediaPipe の人物セグメンテーションと自作の WebGL コンポジターを組み合わせる、LiveKit の track processor と同じやり方である。

## 目標

1. **カメラのオン/オフ。** 参加者のカメラ映像は新しい Track `<id>/camera` で送り出す。ほかの参加者は全員、それをカメラのタイルで見る。
2. **バーチャル背景。** カメラが映像ソースである間、参加者は `none`、`blur`、`image`(同梱の画像 1 枚)から選ぶ。
   - MediaPipe の selfie segmenter で人物を切り出す。
   - アプリが持つ WebGL2 のシェーダーで、エンコードの前に人物と背景を合成する。
   - モードを変えると次のフレームから反映され、カメラも Track も再起動しない。
3. **動画配信のオン/オフ。** オンにすると、保存済みの mp4 を同じカメラの Track で配信する。
   - 既定はアプリに同梱のサンプル mp4。
   - 参加者は代わりに別のローカルの mp4 を選んでもよい。
   - ファイルはループし、映像だけを送る。音声は送らず、ローカルでも再生しない。
4. **Track ごとにソースは 1 つ。** カメラの Track に映像を流すのは、カメラとファイルのどちらか一方だけである。片方が配信中にもう片方を選ぶと、Track を終わらせずにソースを切り替える。
5. **画面共有は独立。** カメラやファイルの配信と並行して動き続ける。

## 対象外

- mp4 の音声の送信。
- 2 枚以上の同梱背景画像、または自分の画像のアップロード。
- カメラデバイスの選択: ブラウザーの既定のカメラを使う。
- カメラの Track の低レート版(Track の切り替え)。

## 失敗とみなすこと

動いたとしても、次のどれかに当たればこの機能は失敗である。

- **部屋が漏れる。** 背景効果を選んでいるときは、セグメンターの読み込み中や読み込みに失敗したあとに、部屋の映像を決して送ってはならない。その間はフレームを送らずに止める(fail-closed)。
- **オフにしたあともカメラを握り続ける。** 参加者がカメラをオフにしたとき、退出したとき、ファイルに切り替えたときには、カメラのランプが消えなければならない。参加者がすでに切り替えたあとでカメラの許可のプロンプトが解決した場合も含む。
- **チャット、音声、画面共有を壊す。** カメラの失敗でこれらを壊してはならない。画面共有が従っているのと同じ分離の決まりである。

## 制約

- フロントエンドは GitHub Pages の `/wired/moqt_chat/` の下にある静的エクスポートである。MediaPipe の wasm(約 13.5 MB)とモデル(約 250 KB)は、CDN ではなくアプリ自身のオリジンとベースパスから配信する。
- **ハブの容量。** ハブのピアごとの Track の上限はこれまで 4(chat、audio、screen、screen-lo)だったが、カメラは 5 本目の Track である。`WIRED_MOQTRUN_MAX_TRACKS_PER_PEER` を 5 にする。満員のルームではピアごとに 24 本のリクエストストリームが要るようになるので、`WIRED_MOQTRUN_MAX_REQS` を 128(セッションあたり 32)にする。
- **Track Alias。** chat が 0..3、audio が 4..7、screen が 10..13、screen-lo が 14..17 を使うので、カメラは 18..21 を取る。クライアントの受信ストリームの振り分けは、音声へのフォールバックより前にカメラの範囲を確かめる。

## 方式の比較

| 方式 | トレードオフ | 判断 |
|---|---|---|
| MediaPipe Tasks Vision `ImageSegmenter` + 自作の WebGL2 コンポジター | 依存は 1 つ。すべて自分で制御できる。wasm は自前で配信 | **採用**(依頼どおり) |
| `@livekit/track-processors` | デモまでは最速だが、LiveKit の Track を前提に作られている | 不採用 |
| Chrome の `backgroundBlur` 制約 | 使えるプラットフォームが限られ、ぼかしのみ | 不採用 |

## 設計

### トランスポート

- 画面共有のクライアント(`MoqtScreenClient`)は、Track の種類を表す記述子を受け取る。カメラのインスタンスは `<id>/camera` を Alias 18 + インデックスで公開し、名前空間 `[id, "camera"]` を告知する。lo 版はない。
- 既存のエンコーダーのパイプラインを、2 か所だけ変えて使い回す。カメラはコンテンツヒントを `motion` にし、エンコーダーは各フレームの可視サイズに従う(`<video>` から取ったフレームは、符号化サイズにパディングを含むためである)。VP8 で、480 B のチャンク、2 秒ごとのキーフレームでエンコードする。
- ソースの切り替えではキーフレームを強制し、受信側が新しいソースをデコードできるようにする。

### ソースのライフサイクル

純粋な状態機械(イベントを受け取り、状態と効果を返す)がソースを管理する。

- **イベント:**
  - ユーザーから: SelectCamera、SelectFile、Off、SetBackground、Leave
  - 遅れて、順不同で、あるいはまったく届かないかもしれない完了通知: カメラの取得成功/失敗、ファイルの再生開始/失敗、セグメンターの準備完了/失敗
  - 動作中の Track から: 配信中のソースの公開、エンコード、フレームの失敗。ソースが自分で終わった場合(カメラが抜かれた、許可が取り消された)も含み、エラーとともにソースをオフにする。また、準備が済んだセグメンターがあとで失われた場合(たとえば WebGL コンテキストの喪失。セグメンターの失敗として扱う)
- **世代。** 取得のたびに世代番号を付ける。古い世代からの完了通知は解放し、決して公開しない。
- **効果** は、フックが持つコントローラーが実行する。取得、解放、Track の公開または終了、セグメンターの読み込みまたはクローズ、エラーの表示である。
- **フレームのゲート。** カメラのフレームごとに、モードが none なら加工せずに送る。セグメンターの準備ができていれば合成し、それ以外は捨てる。
- **フレーム単位の fail-closed。** 合成したフレームを送るのは、セグメンターがまさにそのフレームのマスクを返し、コンポジターがそれを描いたときだけである。セグメンテーションが例外を投げたりマスクを返さなかったりしたら、そのフレームは捨てる。コンポジターを作れないときや、その WebGL コンテキストが失われたときも同じで、この 2 つの失敗はセグメンターの失敗としても数える。エラーを表示し、背景を none にするまでフレームは送らない。加工していないフレームを代わりに送ることは決してない。

### 背景

- **読み込み。** `segmenter.ts` は `ImageSegmenter`(selfie segmenter、VIDEO モード)を `<basePath>/mediapipe/` から遅延読み込みす。まず GPU デリゲートを試し、だめなら CPU に切り替える。
- **マスク。** セグメンターの confidence mask を float として読み、8 ビットのテクスチャーとしてアップロードする。
- **合成。** `backgroundCompositor.ts` はオフスクリーンの WebGL2 キャンバスに `mix(background, person, smoothstep(lo, hi, mask))` を描く。背景はフレームをぼかしたコピーか、同梱の画像である。キャンバスから新しい `VideoFrame` を取ってエンコーダーに渡す。ローカルのプレビューもその同じフレームを描く。

### 受信

- カメラの受信パイプライン(送信者ごとにデコーダー)とカメラのタイルは、画面共有のタイルとは分けて持つ。
- 名前空間が取り下げられるか、フレームが止まると、タイルを取り除く。

### UI

サイドのレールに Video の節を加える。

- Camera のトグル
- Background の選択: none / blur / image
- Video file のトグル(同梱の mp4 か、選んだファイルを配信する)

ソースをオンにするには接続が必要である。接続が切れたら、自動の再参加を待たずに、配信中のソースをすぐにオフにする(カメラやファイルを解放し、Track の公開を取り消す)。それでも、ソースがまだ配信中だった場合の保険として、切断中も配信中のソースのトグルは押せるままにする。エラーはこの節の下に表示する。カメラのタイルは画面共有のタイルの隣に表示する。

## 受け入れ基準

- カメラをオンにすると、カメラを取得してカメラの Track を公開する。ファイルをオンにすると、ファイルを再生して同じ Track を公開する。
- カメラとファイルを切り替えても、Track は公開されたままである。新しいソースが立ち上がったら、そのソースのフレームだけを送る。新しいソースが失敗したら、Track は終わる。
- ソースをオフにすると、Track を終わらせ、カメラ、ファイル、セグメンターを解放する。
- ユーザーがオフにした、または切り替えたあとで立ち上がったカメラやファイルは、すぐに解放し、決して送らない。
- blur か image を選んでいるときは、セグメンターの読み込み中や失敗後にカメラのフレームを送らない。
- blur と image の間で切り替えても、読み込んだセグメンターはそのままで、カメラも再起動しない。none を選ぶとセグメンターを閉じる。
- ファイルのソースは背景を無視する。
- 開けないカメラ、再生できないファイル、公開・エンコード・フレームが失敗した(または自分で終わった)配信中のソースは、オフに戻ってエラーを表示する。エラーは次に選び直すまで残る。
- ルームを退出すると、取得途中のものも含めてすべてを解放する。
- 接続が切れたら、ソースはすぐにオフになる。

## 検証

- ソースのライフサイクルの振る舞いは実装の前に固め、上の受け入れ基準をそれぞれ状態機械かコントローラーの単体テストにする。
- **単体テスト** で、フレームのゲート、Alias の範囲と振り分け、Track の種類を確かめる。
- **e2e** では偽のカメラを使うヘッドレス Chrome の参加者を 2 人動かす。
  - カメラをオン: 相手のカメラのタイルがフレームを受け取る
  - blur 背景: ぼかしたフレームが届き続け、タイルは偽のカメラの色を保つ
  - image 背景: 偽のカメラには人物が映っていないので、タイルは同梱画像の色になる
  - mp4 に切り替え: フレームサイズが mp4 のものに変わる
  - オフ: タイルが消え、1 秒後にはフレームがデコードされていない
  - 途中から参加した人にも、配信中のカメラの Track が見える
  - 送信者は自分のプレビューを見られ、視聴者のタイルには送信者の名前が出る
  - クラッシュした送信者は、フレームが止まった時点でタイルを失う
  - 接続が切れると、カメラはすぐにオフになり、そのトグルもロックされる
