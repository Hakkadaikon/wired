A browser sends its page's Origin on every WebTransport Extended CONNECT.
This server accepts one Origin and rejects every other with `403`, before any
session is established.

<Example id="wt-origin" />

## How it works

- `opt.wt_origin_check` runs after `wt_resource_check` (if any) accepted and
  before the session exists. Returning `0` answers `403` with no session;
  the default (`0`, unset) accepts every well-formed Origin.
- `origin` is the CONNECT's `Origin` header as a view, valid only during the
  call. A CONNECT sent with an explicitly empty `Origin: ` never reaches this
  callback at all: the SDK itself answers `403` for a present-but-empty
  Origin before `wt_origin_check` runs. Only a CONNECT sent with no `Origin`
  header at all arrives here, as an empty span.
- `authority` (the CONNECT's `:authority`) is also available, for a check
  that varies by virtual host; this page ignores it.
- Both requests target the same `/chat` path, so the only thing that
  differs between the two client calls below is the Origin header.
