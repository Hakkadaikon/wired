A server that uses a real certificate reads it from a `cert.pem`/`key.pem`
pair. This page decodes the pair step by step, then loads it with one call.
The pair is a self-signed demo for `localhost`.

<Example id="tls-certificates" />

## How it works

- `wired_fio_read(path, buf)` reads a whole file into a caller-owned buffer.
- `wired_pem_next(text, &at, &label, &der)` decodes the next PEM block to
  DER and advances `at`. Call it in a loop to walk a fullchain file.
- `wired_eckey_p256_priv(der, priv)` extracts the P-256 private key from
  SEC1 or PKCS#8 DER.
- `wired_certreload_load(cert, key, &store, &id)` does all of the above and
  points `id.chain`/`id.chain_count`/`id.cert_seed` at `store`. Keep
  `store` alive as long as `id` is in use.

## Client certificates (mutual TLS)

By default only the server proves who it is. To make each client prove its
identity too, set two fields of the server identity before serving:

- `id.client_auth = WIRED_CLIENT_AUTH_REQUIRED` refuses a client that sends
  no certificate. `WIRED_CLIENT_AUTH_OPTIONAL` lets it in without one.
- `id.client_ca` points at a trust store (`castore_init` + `castore_add`
  with your client CA's DER). The server reads the store, its
  `castore_entry` array and every CA DER buffer on each handshake without
  copying them, so define all three where they outlive the server: in
  `main` or as `static` variables, not as locals of a setup helper that
  returns before `wired_server_run`.
- Client auth without a trust store fails, so a typo cannot let everyone
  in. Every connection is then refused: each client gets an Initial
  CONNECTION_CLOSE with CRYPTO_ERROR 0x128 (handshake_failure), no
  handler ever runs, and a `-DWIRED_DEBUG` build logs
  `srvboot accept failed` for each attempt.

A client certificate must chain to that CA, be valid now, and allow
`clientAuth` if it lists key purposes. The HTTP handler then finds the
client's leaf certificate in `x->peer_cert` (empty when the client sent
none under the optional mode). With client auth on, session resumption and
0-RTT are turned off, because a resumed connection would carry no proof of
the client's key.
