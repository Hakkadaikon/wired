When bandwidth is short, audio should beat video; when a server must go
down, its sessions should get a new address and time to leave instead of
a dropped connection. This page shows both: two subscriptions with
different priorities, whose relay streams get different send classes, and a
drain where the hub sends GOAWAY, refuses new requests, ends the granted
subscriptions, and closes the session when the grace runs out.

## How it works

- SUBSCRIBE carries the SUBSCRIBER_PRIORITY parameter (0..255, lower is
  more important, 128 when absent — draft-ietf-moq-transport-22 9.20.7,
  5.1.1). The stream itself carries the Publisher Priority in its
  SUBGROUP_HEADER. When the hub opens a subscriber's relay stream it
  gives the stream a send class (`wired_wt_sched`): RFC 9218 urgency 4,
  then `subscriber << 8 | publisher` as a second key (5.1.2 orders by
  subscriber priority, then publisher priority), then a place inside the
  subscription (group order, and a fill stream before the live stream of
  the same group). Control and request streams keep the transport
  default urgency 3 and so go first, as 5.1.2 recommends.
- The class reaches the transport through the hub's `stream_sched` io
  op, here `wired_server_wt_stream_schedule` wrapped in a logger: audio
  (priority 10) and video (priority 200) share urgency 4, and the lower
  second key sends audio bytes before video bytes under pressure. The
  log shows the class; the scheduling itself is the transport's job.
- `wired_moqt_goaway(hub, new_uri, timeout_ms)` sends GOAWAY (9.2)
  with the New Session URI on every session's control stream, which in the
  `moqt-22` sessions of this sample is the server's unidirectional one
  (6.6.1 describes the migration). This demo
  triggers it with any datagram; a real server calls it on SIGTERM or
  before a deploy. The URI may be up to `WIRED_MOQTRUN_GOAWAY_URI_MAX`
  (8192) bytes.
- After GOAWAY every new request on that session is answered
  REQUEST_ERROR with error code GOING_AWAY (0x6): the client is expected
  to take its next request to `new_uri`. A client SHOULD NOT start new
  requests after GOAWAY (9.2); this sample sends one SUBSCRIBE on purpose
  to show the GOING_AWAY answer.
- The subscriptions already granted keep flowing until the timeout. The
  hub's tick (`wired_moqt_tick` from `on_step`) enforces it: once
  `timeout_ms` passes, each subscription's relay streams are reset and
  the subscription ends with PUBLISH_DONE (9.9) status GOING_AWAY (0x4)
  on its request stream.
- This client keeps its request streams open past the deadline, so on
  the next tick the hub closes the session with the GOAWAY_TIMEOUT
  session code (0x10, `WIRED_MOQTRUN_CLOSE_GOAWAY_TIMEOUT`). A client
  that closes its own streams and session in time never hits it.
- A peer can also ask to leave: WT_DRAIN_SESSION wired to
  `wired_moqt_on_session_draining` drains that one session the same way,
  with an empty URI and a 5000 ms grace.
