A clock-paced track: `wired_moqt_publish_live` turns a fragmented MP4's
fragments into successive Groups, one every `group_ms`, each sent to every
subscriber the moment the server's clock enters it.

<Example id="moqt-live" />

## How it works

- `mp4frag_scan` walks a fragmented MP4's top-level boxes (ISO/IEC 14496-12)
  into an init segment (`ftyp`+`moov`) and a list of `moof`+`mdat` fragment
  views -- no sample-table parsing, just the boundaries a publisher needs.
  `movie-live.mp4` (committed next to `main.c`, regenerate with
  `gen_movie.py`) is a tiny synthetic file: real box structure, filler media
  bytes, so this page is about MoQT Group delivery, not video decoding.
- `wired_moqt_publish_blob` still publishes the init segment as its own
  track (`movie/init`), exactly like the previous page.
- `wired_moqt_publish_live(&hub, name, alias, frags, n_frags, group_ms,
  now_ms)` publishes the fragments as track `movie`: Group `g` carries
  fragment `g mod n_frags`. A SUBSCRIBE gets SUBSCRIBE_OK and the current
  Group at once; `wired_moqt_tick`, wired to `wired_srvrun_opt.on_step`,
  sends each later Group the moment the clock enters it.
- `now_ms` (Group 0's start) is captured at the *first WebTransport
  session*, not at server boot: `publish_live_once` (called from
  `wt_on_session`) runs exactly once, at the moment a client actually
  connects. Capturing it at boot instead would fold the client's own
  connect/handshake latency into Group 0's window -- on a loaded machine
  that can exceed `group_ms` and shift which fragment Group 0 (and so
  every later Group) carries.
- Group delivery needs a second io entry, `send_uni2`: the hub builds a
  short framing prefix (`head`) in front of a fragment it only holds as a
  view (`body`), and the adapter concatenates both behind the WebTransport
  signal into its own staging. That staging must survive until the SDK
  reports the stream no longer `wired_server_wt_stream_inflight` -- this
  page keeps a small ring of slots for that reason, the same pattern
  `examples/moqt_chat`'s server uses at a larger scale.
