`obs.cert_path`/`obs.key_path` enable a `SIGHUP`-triggered certificate
reload: an operator drops a new PEM pair at the same path, signals the
process, and every connection cold-started afterward uses the new identity
-- a connection already past its handshake is never disturbed.

<Example id="ops-cert-reload" />

## How it works

- `obs.cert_path`/`obs.key_path` (both set) install a `SIGHUP` handler
  inside `wired_server_run_opt`; on receipt it re-reads and re-decodes the
  same PEM pair and updates `chain`/`chain_count`/`cert_seed` of the
  identity the run is serving. The run copied `id` at start, so that is its
  own copy: the caller's `id` is neither read nor written after the call.
- This page's `on_step` hook reads the served identity through
  `wired_server_run_id()` on every tick and logs the leaf certificate's
  SHA-256 whenever it changes: once at startup, and again right after the
  reload.
- The replacement PEM pair is written to `live-cert.pem`/`live-key.pem`
  (the same path `obs.cert_path`/`obs.key_path` name, gitignored since the
  server itself seeds and replaces it -- `CERT_A`/`CERT_B` in `main.c` are
  the actual source) once, early -- standing in for an operator's deploy
  step -- which is safe because the server keeps its already-loaded
  identity until the `SIGHUP` actually arrives.
- `probe tls --fp` prints the same leaf fingerprint from the client side,
  independently confirming the second handshake sees the new certificate.
