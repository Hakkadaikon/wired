Four server options that do not change what a connection carries, only how
it gets there and what gets logged alongside it: session-ticket
resumption, RFC 9000 8.1.2 Retry, the congestion controller, and qlog/NSS
key log output.

<Example id="ops-handshake-knobs" />

## How it works

- `id.ticket_key = wired_srvloop_ticket_key()` enables session-ticket
  resumption (RFC 8446 4.6.1, 0-RTT's prerequisite). The ticket key is
  derived from that seed (here the SDK's per-process draw) and rotates
  every two hours: the current key seals new tickets, and the current or
  previous key opens presented ones. A ticket older than that is ignored
  and the client gets a full handshake. Any 32-byte secret works as the
  seed; set the same one on every server behind an address, and across
  restarts, to keep tickets valid there.
  `wired_srvkeys_set_token_key(seed)`, called before the server starts, does
  the same for Retry and NEW_TOKEN tokens. A seed is a long-term root
  secret: generate 32 bytes from a CSPRNG and keep it secret; changing it
  invalidates outstanding tickets or tokens. Use separate secrets for the
  two; reusing one is not catastrophic, because purpose labels keep the
  derived keys apart. The 0-RTT replay record is per process, so with a
  shared seed early data can be replayed once per server: do not enable
  `early_data` across servers that share a seed.
- Resumption alone does not accept 0-RTT: RFC 8446 Appendix E.5 requires
  the application to ask for it, since 0-RTT data can be replayed. Set
  `id.early_data = 1` as well only when every request a client may send
  early is safe to process twice. This page leaves it off.
- `opt.force_retry = 1` makes every Initial without a valid Retry token
  get a stateless Retry first (RFC 9000 8.1.2) -- the quic-interop-runner's
  retry testcase's server mode. A real client handles this transparently;
  the handshake still completes, just with one extra round trip.
- `obs.cc_algo` picks the congestion controller for fresh connections
  (`CC_ALGO_NEWRENO` 0, `CC_ALGO_CUBIC` 1, `CC_ALGO_BBR` 2, see
  `transport/recovery/congestion/cc/cc.h`); `0` with no build override
  means Cubic (`WIRED_CC_ALGO_DEFAULT` in srvrun.c), since an explicit
  runtime NewReno request is itself `0` and indistinguishable from
  "unset" -- a build wanting NewReno by default overrides
  `-DWIRED_CC_ALGO_DEFAULT=0` instead.
- `obs.qlog_path` / `obs.keylog_path` write a qlog (RFC 9002-shaped
  `packet_sent`/`packet_received` events) and an NSS key log
  (`SSLKEYLOGFILE` format) a tool like Wireshark reads to decrypt a
  capture -- both 0 by default.
