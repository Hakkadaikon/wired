`wired_srvrun_opt.on_step` は、接続が生きているかどうかにかかわらず、
イベントループの 1 ステップごとに 1 回実行されます。
クロックのティックや定期的なフラッシュなど、通信相手（ピア）のスケジュールではなくアプリ自身のスケジュールで動かしたい処理に使います。

<Example id="ops-timers" />

## 仕組み

- `opt.on_step = on_step` でこのフックを登録します。
  フックが登録されている間、ループは必ずタイムアウト付きで待つようになるので、
  通信が何もなくても少なくとも `SRVRUN_PTO_MS`（25ms）ごとに発火し続けます。
- このフックには、ループ自身の単調増加クロック（`now_ms`）が渡されます。
  このページでは、クロックの値そのものではなく、固定した回数だけをログに出します。
  クライアントが接続するまでにサーバーが実際に動いていた時間の長さに関わらず、
  golden（期待値として保存してある出力）の長さを変えないためです。
- リクエストやデータグラムのコールバックと同じように、このフックの中からも
  `wired_server_wt_*` の送信 API をすべて呼べます。ループの内側で実行されるからです。
