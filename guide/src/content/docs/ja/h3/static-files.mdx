`wired_staticfile_resolve` は、リクエストパスをドキュメントルート下のファイルパスに変換し、パストラバーサル（`..` を使ってドキュメントルートの外へ抜け出す攻撃）を拒否します。
`wired_mimetype_for_path` は、その拡張子から Content-Type を選びます。
このページのサーバーは、この例のディレクトリに置いた 2 つのファイルを配信し、それ以外のパスには 404 を返します。

<Example id="h3-static-files" />

## 仕組み

- `wired_staticfile_resolve(".", reqpath, "index.html", resolved, cap)` は、
  リクエストパスを現在のディレクトリ下に解決し、`..` を含むセグメントを拒否します。
- `wired_mimetype_for_path(resolved)` は、解決済みパスの拡張子を読みます
  （`.txt` は `text/plain`、`.html` は `text/html`）。
  この呼び出しは最初のラウンド（ハンドラーが呼ばれる 1 回分の処理）で一度だけ行い、`wired_h3reqdrive` 自身の content-type フィールドと同じ扱いにします。
- `wired_fio_open` / `wired_fio_size` / `wired_fio_pread` / `wired_fio_close` は、
  `x->body->cap` 単位でファイルをチャンク読みします。
  `word_list` の例が、1 ラウンドより大きいドキュメントルートで使っているのと同じ読み方です。
- ファイルが見つからない場合、または `wired_staticfile_resolve` が拒否した場合は、
  `x->status`（`wired_http_handler`、[パスによる振り分け](../routing/) ページで直した仕組みと同じ）で本物の 404 を返します。
