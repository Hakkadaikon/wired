`wired_srvrun_handler.on_body` は、リクエストボディを SDK が丸ごと（固定の一つのウィンドウ分まで）
バッファーしてからハンドラーを呼ぶのではなく、届いたボディを順にストリーミングで受け取ります。
このページは、ボディのバイト数を積算してそれをレスポンスとして返しつつ、
自前で 4096 バイトの上限を課します。
上限を超えたボディはその場で受信を打ち切り、`413` を自動的に返します。
これは SDK 自身のウィンドウオーバーフローが返す場合と同じステータスです。

## 仕組み

- `wired_srvrun_handler.on_body` は、DATA の 1 チャンクごとに順番に呼ばれ、
  最後の呼び出しだけ `fin=1` になります。`req` はすでにデコードされています
  （メソッド、パス、ヘッダー）が、ボディをこのコールバック経由で受け取っているため
  `req->body` 自体は空のままです。
- `0` を返すとボディの受信はその場で止まります。そのストリームに対する以降の呼び出しはなく、
  レスポンスは `413` になります（その場合 `wired_http_handler` は呼ばれません）。
  このページは、積算値が `APP_BODY_LIMIT`（4096 バイト）を超えた時点で 0 を返します。
- チャンクの境目は、クライアント側の QUIC 送信パケタイズに従うため、実行ごとに固定ではありません。
  ページの出力を決定的にするため、ログに出すのはボディ全体が揃った時点の合計だけです。
- `on_body` と一緒に設定した `wired_http_handler` は、ボディが打ち切られずに完結した場合にだけ呼ばれ、
  積算した合計をそのまま返します。
