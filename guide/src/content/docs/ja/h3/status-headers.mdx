`wired_http_handler` は、ボディだけを返すのではなく `wired_http_exchange` 全体を埋めるハンドラーです。
そのため、レスポンスのステータスを設定したり、ヘッダーフィールドを追加したりできます。
このページのサーバーは、リダイレクトとクッキーの発行を行い、`Authorization` ヘッダーまたはクッキーを読んで応答を決めます。

## 仕組み

- `/redirect` は `x->status = 302` を設定し、`x->fields[0]` に `location: /target` を 1 つ入れ、
  0 を返してボディなしの応答にします。
- `/login` は 200 のボディと一緒に `set-cookie` フィールドを設定します。
- `/secret` は `wired_http_req_header(req, "authorization", &v)` で通常のヘッダーを名前で読み、
  `req->cookie` と `req->cookie_len` を直接読みます。
  クッキーは専用のフィールドであり、`wired_http_req_header` 経由では読めません（そのドキュメントコメントを参照）。
- `x->fields` には最大 `WIRED_HTTP_MAX_FIELDS`（8）個まで入ります。
  各要素は `wired_http_field`（name、value の組）で、どちらもワイヤー上（実際に送られるバイト列の上）では小文字です（RFC 9114 4.2）。
- probe クライアントの `h3req -H 'name: value'` は、追加のリクエストヘッダーを 1 つ送ります。
  また `CheckRedirect` を無効にしているので、302 を隠したまま `/target` へ自動で追従することはなく、302 そのものを表示します。
