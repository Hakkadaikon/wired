セッションの終わり方は、コネクションの切断だけではありません。
このサーバーは、セッションごとに小さな状態を持ちます。
最初のデータグラムを受け取るとクライアントに終了の準備を促し、2 つ目を受け取るとアプリケーションのコードと理由を付けてセッションを閉じます。

## 仕組み

- アプリの状態は、`wired_wt_session` のポインターをキーにした小さな表に置きます。
  `wt_on_session` で枠を確保し、`wt_on_session_close` で解放します。
  SDK はセッションの領域を後のコネクションで再利用します。
  解放し忘れた枠は、同じポインターに当たった次のクライアントに、終わったセッションの状態を引き継がせてしまいます。
- `wired_server_wt_drain_session(s)` は `WT_DRAIN_SESSION` を送ります。
  これは、近いうちに終えるよう求める要求です。
  セッションは開いたままなので、2 つ目のデータグラムも届きます。
  送るのはセッションごとに 1 回までです。
- クライアント側の webtransport-go v0.13 には、drain を扱う API がありません。
  未知のカプセル（WebTransport の制御用メッセージ）として読み飛ばすため、クライアントの出力には何も現れません。
- `wired_server_wt_close_session(s, 4001, reason)` は、そのコードと理由を載せた `WT_CLOSE_SESSION` を送り、セッションを終えます。
  送信はその場では行わずキューに積み、理由の文字列はコピーします。
  クライアントには、同じコードと理由を持つ `*webtransport.SessionError` として届きます。
- サーバーは、コネクションが閉じる前に `session closed` をログに出します。
  セッションを終えたのがサーバー自身だからです。
  クライアントは、そのあとで QUIC コネクションを閉じます。
- 逆向きもあります。
  `opt.wt_on_session_draining` を登録すると、クライアントが `WT_DRAIN_SESSION` を送ったことを受け取れます。
  クライアントが何度送っても、呼ばれるのはセッションごとに 1 回です。
  webtransport-go v0.13 は drain を送れないため、このページでは示していません。
