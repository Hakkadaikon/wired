`wired.h` には、libc（C の標準ライブラリ）を使わない printf として `wired_snprintf`、`wired_vsnprintf`、`wired_dprintf`、`wired_obuf_printf` があります。
4 つとも同じ書式を受け付けます。

## C と同じ変換

変換は、`%d` のように `%` の後に続く文字で、引数をどの形で出すかを決めます。
`%d %i %u %x %X %p %s %c %% %f` が使えます。
長さ修飾子（`%lld` の `ll` のように、引数の型の大きさを示す文字）は `hh h l ll z`、フラグは `-` `0` `+` 空白 `#` です。
幅（最低何文字で出すか）と精度（`%s` なら最大何文字まで出すか）には、数字か `*` を書けます。
`*` と書くと、その値を引数から受け取ります。
`%.*s` と `WIRED_SPAN_ARG(span)` を組み合わせると、末尾に NUL（文字列の終わりを示す 0 のバイト）が付かない `wired_span` を、そのまま文字列として出せます。

C の printf との違いは `common/fmt/fmt.h` の冒頭にまとめてあります。
たとえば `%p` は常に `0x` から始まる小文字の 16 進で出し、NULL は `0x0` になります。

## バイト列の 16 進: %H

`%H` は wired 独自の変換で、C の printf にはありません。
バイト列を、区切りのない小文字の 16 進で出します。

| 書き方 | 引数 | 出すもの |
|---|---|---|
| `%.*H` | `int n, const u8* p` | `p` から `n` バイト |
| `%.32H` | `const u8* p` | `p` から 32 バイト |
| `%H` | `const u8* p` | 何も出さない（ポインターは読み飛ばす） |

```c
u8 digest[SHA256_DIGEST];
wired_sha256((const u8*)"abc", 3, digest);
wired_dprintf(2, "sha256 = %.*H\n", (int)sizeof digest, digest);
```

`%.*H` の引数の並びは `%.*s` と同じなので、`wired_span` は `WIRED_SPAN_ARG` でそのまま渡せます。

```c
wired_dprintf(2, "dcid=%.*H\n", WIRED_SPAN_ARG(dcid));
```

`%H` を使うときは、次の点が `%s` と違います。

- 精度は出力の文字数ではなく、入力のバイト数です。`%.4H` は 4 バイトを 8 文字で出します。
- 精度を書かない `%H` は 0 バイトとして扱います。何も出しませんが、ポインターの引数は 1 つ読み進めるので、後ろの引数はずれません。
- ポインターが NULL で、バイト数が 1 以上なら `(null)` を出します。
- 幅と `-` フラグは、出した 16 進の文字列全体の左右を空白で埋めます。
- 長さの上限はありません。内部でバッファーにためず、1 バイトずつ出力先へ書きます。

C 標準に無い変換なので、`%H` の書式文字列を libc の printf に渡しても同じ結果にはなりません。

## 知らない変換

wired が知らない変換（たとえば `%q`）は、`%` とその文字をそのまま出します。
その前に `*` の幅や精度があると、その `int` の引数はすでに読まれているので、後ろの引数が 1 つずれます。
C でも知らない変換の動作は決まっていないので、書式と引数の数を合わせてください。
