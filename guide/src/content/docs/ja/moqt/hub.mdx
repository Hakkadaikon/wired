MoQT（Media over QUIC Transport）は、映像や音声などのメディアを QUIC の上で運ぶためのプロトコルです。
そのサーバーは、WebTransport のコールバックの上に置いた `wired_moqt_hub` です。
接続時に相手が提示する WebTransport のサブプロトコル（`moqt-18`/`moqt-19`/`moqt-22`）に応じて、draft-ietf-moq-transport の 18/19/22 のいずれかを選んで話します。
このガイドの説明では draft-19 の節番号を使いますが、よく使う節（制御ストリームや SETUP の仕組み）は 3 つの版でバイト単位まで同じなので、そのまま読み進められます。
このページではハブだけを動かし、接続したクライアントがサーバーの SETUP（セッションを始める最初のメッセージ）を受け取ります。

## 仕組み

- `wired_moqt_init(&hub, io)` がハブを初期化します。
  `io` は、ハブが使う WebTransport の送信関数の表です。
  `wired_server_wt_stream_send` はそのまま渡せます。
  ストリームを開く 2 つの呼び出しには、先頭にストリームシグナル（目印のバイト列）が必要なので、`with_signal` が `wired_wtwire_signal_put` でそれを付けます。
- ハブの `wired_moqt_on_session`、`_on_stream_data`、`_on_datagram`、`_on_session_close` は、それぞれ `&hub` をコンテキストにして `wired_srvrun_opt` にそのまま設定します。
  サーバーを動かすのは `wired_server_run_opt` です。
- セッションが開くと、ハブは制御ストリームを開き、その上で SETUP（type `0x2f00`）を送ります。
  このストリームの形は WebTransport のサブプロトコルで決まります。
  `moqt-NN` を交渉したセッションでは、ハブが単方向の制御ストリームを開き、クライアントも自分の単方向の制御ストリームを開きます。
  交渉しなかったセッションは、draft-19 を従来の双方向の制御ストリーム 1 本の上で話します。
  このページのサーバーは `opt.wt_protocols` を設定していないので、そのクライアントは（サブプロトコルを提示できないブラウザと同じく）双方向の形になり、`AcceptStream` で SETUP を読みます。
- クライアントに版を選ばせるには、`wired_moqt_wt_protocols(buf, sizeof buf)` が書き出すハブの一覧（`moqt-22 moqt-19 moqt-18`）を `opt.wt_protocols` に設定します。
  `examples/moqt_interop` がこの使い方をしています。
- サーバーの識別情報で `max_datagram_frame_size` を設定すると、QUIC DATAGRAM（再送しないメッセージを運ぶ QUIC の拡張）が有効になります。
  WebTransport のクライアントはこれを必要とします。
- `moqtrun.h` は `wired.h` に含まれないので、別にインクルードします。
