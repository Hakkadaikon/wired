帯域が足りないときは、音声を映像より先に送るべきです。
サーバーを止めるときは、接続を突然切るのではなく、セッションに移動先と猶予を与えるべきです。
このページでは、その両方を動かします。
優先度の異なる 2 つの購読が、それぞれ別の urgency のリレーストリームを受け取ります。
その後の排水（drain）では、ハブが GOAWAY を送り、新しいリクエストを拒否し、許可済みの購読を終わらせ、猶予が尽きたところでセッションを閉じます。

## 仕組み

- SUBSCRIBE は SUBSCRIBER_PRIORITY パラメータ（0〜255、小さいほど重要、省略時は 128。draft-ietf-moq-transport-19 7.1）を運びます。
  Publisher Priority は、ストリーム自身の SUBGROUP_HEADER が運びます。
  ハブは購読者のリレーストリームを開くとき、この 2 つを 1 つの RFC 9218 urgency（0〜7、小さいほど先）に対応づけます。
  式は `4 + (subscriber >> 7) * 2 + (publisher >> 7)` です。
  購読者側の半分が 4/5 か 6/7 かの組を選び、パブリッシャー側の半分が組の中のどちらかを選びます（7.2 は購読者の優先度、次にパブリッシャーの優先度で順序づけると定めています）。
  制御ストリームとリクエストストリームはトランスポートの既定値 3 のままなので、どのリレーストリームよりも先に送られます（7.2 の推奨どおりです）。
- 対応づけた値は、ハブの io 操作 `stream_priority` を通じてトランスポートに届きます。
  このサンプルでは `wired_server_wt_stream_priority` をログ付きで包んでいます。
  音声（優先度 10）は urgency 5、映像（優先度 200）は urgency 7 になるため、帯域が逼迫したときサーバーは音声のバイトを映像より先に送ります。
  ログが見せるのは対応づけまでで、スケジューリング自体はトランスポートの仕事です。
- `wired_moqt_goaway(hub, new_uri, timeout_ms)` は、すべてのセッションの制御ストリームに、New Session URI 付きの GOAWAY（10.4）を送ります。
  このデモはデータグラムの受信を引き金にしていますが、実際のサーバーなら SIGTERM やデプロイ前に呼びます。
  URI は `WIRED_MOQTRUN_GOAWAY_URI_MAX`（512）バイトまでです。
- GOAWAY の後、そのセッションの新しいリクエストはすべて REQUEST_ERROR で拒否されます。
  エラーコードは GOING_AWAY（0x6）で、クライアントは次のリクエストを `new_uri` に向けることが期待されます。
- 許可済みの購読は、タイムアウトまで流れ続けます。
  期限を守らせるのは、`on_step` から呼ぶハブのティック（`wired_moqt_tick`）です。
  `timeout_ms` が過ぎると、各購読のリレーストリームがリセットされ、購読はそのリクエストストリーム上の PUBLISH_DONE（10.11）ステータス GOING_AWAY（0x4）で終わります。
- このクライアントは期限を過ぎてもリクエストストリームを開いたままにしているため、次のティックでハブがセッションを閉じます。
  セッションコードは GOAWAY_TIMEOUT（0x10、`WIRED_MOQTRUN_CLOSE_GOAWAY_TIMEOUT`）です。
  期限内に自分のストリームとセッションを閉じるクライアントは、このコードを受け取りません。
- ピアの側から退出を求めることもできます。
  WT_DRAIN_SESSION を `wired_moqt_on_session_draining` につなぐと、そのセッションだけが同じ手順で排水されます（URI は空、猶予は 5000 ミリ秒）。
