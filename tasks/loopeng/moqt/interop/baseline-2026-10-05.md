- Date: 2026-10-05

- runner: Hakkadaikon/moq-interop-runner a93b3f1, run as `./run-interop-tests.sh --relay wired` (the same as `make interop-relay RELAY=wired`).
- Final consolidated run: `scratchpad/results-final/` (a copy of `results/2026-10-05_131427`). Result: **3/14 PASS** (moq-dev-js, moq5, moq-dev-rs). This is the same set of clients as CI run 37250572657.

## 0. Environment blocker and workaround (read first)

- The sandbox kernel boots with `ipv6.disable=1` (see `/proc/cmdline`).
  - wired only opens AF_INET6 dual-stack UDP sockets (`src/transport/io/socket/io/udp.c`, `wired_udp_socket`).
  - So `socket(AF_INET6)` returns EAFNOSUPPORT, the relay prints `listen failed` and exits 1.
  - The first plain run was 0/14 (`dependency failed to start`).
  - On GitHub runners IPv6 exists, so this is local-environment only. A robustness note for wired: it has no AF_INET fallback.
- **Workaround, test harness only, no wired source change**: `scratchpad/v6shim/v6shim.c`, a static ptrace wrapper put in front of the image entrypoint. It:
  - rewrites AF_INET6 to AF_INET;
  - converts v4-mapped sockaddrs in place on bind/connect/sendto/sendmsg/sendmmsg and recvfrom/recvmsg/recvmmsg/getsockname;
  - fakes success for `setsockopt(IPPROTO_IPV6, …)`;
  - retries a dual-stack bind on port 0 on EADDRINUSE.
- Some clients also need IPv6: quinn binds `[::]:0`, and picoquic opens both v4 and v6 sockets. Each client was run both natively and through the shim.
- Mode used in the final run:
  - native: aiomoqt, moxygen, moqx, imquic, moq-playa, quic-zig, moqlivemock, xquic-draft-18, moqtopus.
  - shim: moq-dev-js, moq-rs-draft-18, moq5, moq-dev-rs, stitcher-moq.
- Two clients are broken by the shim: aiomoqt (picoquic) and moxygen (mvfst). Their native runs work, so their shim results are discarded.
- The shim also has a small int3 breakpoint tracer (`V6SHIM_BP=name=addr,...`). It logs calls to wired's global functions with arguments, return value and the first 16 bytes at rdi. I used it in place of packet decryption.
- Why not decrypt captures: wired's `--keylog` writes only `CLIENT_HANDSHAKE_TRAFFIC_SECRET` (`src/tls/handshake/roles/server/server.c` `srv_log_c_hs_traffic`), so a pcap cannot be decrypted. This is an observability gap of its own.
- After the runs, image tags were restored to the unshimmed originals.

## 2. wired-side gaps, ranked by cases unblocked

### G1. No upstream SUBSCRIBE to a PUBLISH_NAMESPACE publisher (relay routing). About 9 cases, plus moq-dev-js and moq5 for real

- **Spec**:
  - draft-18 §9 (Relays): forward a downstream SUBSCRIBE upstream to a publisher whose namespace matches.
  - §6.2/§10.15: PUBLISH_NAMESPACE.
  - The runner's `announce-subscribe` success criterion is "Subscriber receives SUBSCRIBE_OK (relay routes subscription to publisher)".
  - `docs/tests/data-plane/README.md` step 5: the relay sends a matching upstream SUBSCRIBE, waits for SUBSCRIBE_OK, then replies downstream.
- **What clients see**: an immediate REQUEST_ERROR code 16 (DOES_NOT_EXIST).
  - aiomoqt: `SUBSCRIBE_ERROR: upstream subscribe failed`.
  - quic-zig: `relay did not route the subscription: code=16`.
  - stitcher (draft-22): `track subscription rejected: not found`, on both announce-subscribe and subscribe-before-announce, because stitcher subscribes only after it sees the announce.
  - moq5: the publisher never receives a SUBSCRIBE (`publisher accepted subscribe: timeout`).
  - moq-playa: `expected SUBSCRIBE_OK, got REQUEST_ERROR`.
  - moq-dev-js: code=16, which it tolerates.
- **wired code**:
  - `src/app/moqt/run/moqtrun.c` `moqtrun_route_peer_subscribe` (~l.1492): only `moqtrun_find_published_track` (PUBLISHed tracks) is consulted, else DOES_NOT_EXIST.
  - The hub explicitly "sends no SUBSCRIBE or REQUEST_UPDATE of its own toward a publisher" (comment at ~l.5802).
  - The wired ledger encodes this as MQ18-052 (`docs/features/draft-moq-transport-18.md:363`), which is narrower than the spec.
- **Needed**:
  1. On a SUBSCRIBE miss, look up a peer whose PUBLISH_NAMESPACE prefix matches.
  2. Open an upstream SUBSCRIBE (a new request stream from the hub) and keep the downstream request pending.
  3. On upstream SUBSCRIBE_OK, map the alias and reply SUBSCRIBE_OK downstream.
  4. Forward upstream data streams and datagrams by alias, and propagate REQUEST_ERROR or PUBLISH_DONE.
- **Unblocks**: announce-subscribe for aiomoqt, quic-zig, stitcher, moq5 and moq-playa (still needs G4), plus stitcher sba. That is 6 cases, and moq-dev-js would pass for real. With G2 it is also the basis for publish-namespace-routed data tests.

### G2. RENDEZVOUS_TIMEOUT is not acted on: SUBSCRIBE is not held for a later PUBLISH, and no TIMEOUT error. 11 cases (moq-rs-draft-18 ×10, quic-zig ×1)

- **Spec**: draft-18 §10.2.6 RENDEZVOUS_TIMEOUT; §5.1; §10.6 REQUEST_ERROR TIMEOUT.
- **What clients send and expect**:
  - `rendezvous-timeout` (moq-rs-d18, quic-zig): SUBSCRIBE `nonexistent/rendezvous`/`test-track` with RENDEZVOUS_TIMEOUT=500 ms. They expect REQUEST_ERROR **TIMEOUT**.
    - wired answers code 16 at once. quic-zig reports `REQUEST_ERROR code=16, expected TIMEOUT (2)`; moq-rs reports `expected REQUEST_ERROR TIMEOUT, got: not found`.
  - `moq-test-*` (9 cases, moq-rs-d18 `moq-test-client/src/moqtest.rs` `run()`):
    1. The subscriber SUBSCRIBEs first with RENDEZVOUS_TIMEOUT.
    2. 200 ms later the publisher sends a direct PUBLISH of the same track.
    3. The relay must hold the SUBSCRIBE and bind it when the PUBLISH arrives.
    - wired answers code 16 at once, so `subscriber setup failed before generation started`.
- **wired code**:
  - The parameter is decoded only (`src/app/moqt/ctl/moqctl.c:869`, `MOQCTL_PARAM_RENDEZVOUS_TIMEOUT`). It is listed as out of scope in `docs/features/draft-moq-transport-18.md:1466`.
  - The pending hold belongs in `moqtrun_route_peer_subscribe`. The bind on arrival belongs in the PUBLISH acceptance path (`moqtrun_dispatch_publish`), and a timer in the hub's step tick should send TIMEOUT.
- **Note**: the 9 moq-test-* cases then also need G3 (PUBLISH_DONE with an exact Stream Count). They also check full data fidelity: subgroup mapping, EOG, extensions, datagram flags, and FORWARD=0 producing no data plus PUBLISH_DONE count 0. G2 alone will not turn them green.

### G3. Inbound PUBLISH_DONE from a publisher is dropped, not forwarded downstream. 1 case now (moq-rs publish-track-subscribe), plus a prerequisite for the 9 moq-test-*

- **Spec**: draft-18 §10.11 PUBLISH_DONE (Stream Count); §9 relays.
- **Evidence**: moq-rs-d18 `publish-track-subscribe` with RUST_LOG trace:
  - The PUBLISH is accepted.
  - The subscriber gets SUBSCRIBE_OK and receives the object, a subgroup with a 23-byte payload, correctly.
  - The publisher then writes PUBLISH_DONE (19 bytes).
  - The subscriber never gets PUBLISH_DONE, so `subscribe()` never resolves and the test times out after 10 s.
- **wired code**: `src/app/moqt/run/moqtrun.c` ~l.3963, where `{MOQCTL_T_PUBLISH_DONE, moqtrun_dispatch_skip}` is accepted on the PUBLISH request stream (`moqtrun_req_done_ok`) and ignored.
- **Needed**: on an inbound PUBLISH_DONE for track T, emit PUBLISH_DONE to each downstream subscription of T. The machinery already exists: `moqtrun_track_done_peer`/`moqtrun_sub_done` (~l.6770–6940). Use the status from upstream (TRACK_ENDED), and the per-subscriber Stream Count it already tracks (`sub->stream_count`).

### G4. HTTP/3 request stream: a reserved (GREASE) frame before HEADERS stalls Extended CONNECT forever. 12 cases (moxygen ×6, moqx ×6)

- **Spec**: RFC 9114 §7.2.8 and §9: reserved frame types `0x1f*N+0x21` may appear on any stream and MUST be ignored.
- **Evidence**:
  - Breakpoint trace of `h3_frame_get` on the request-stream accumulator:
    - moxygen: bytes `40 fa 00 | 01 40 71 …`, i.e. frame type 0xfa (=0x1f·7+0x21), length 0, then HEADERS of 113 bytes.
    - moqx: `41 38 00 | 01 40 5f …` (0x138 = 0x1f·9+0x21).
  - `h3_frame_get` returns the 3-byte grease frame, and `wired_h3reqdrive_recv_get` is never called.
  - The client log shows CONNECT HEADERS acked, then `proxygen::HTTPException: ingress timeout, streamID=0, timeout=2000ms`.
- **wired code**: `src/app/http3/server/srvloop/dispatch.c`:
  - `acc_headers_frame_len` (~l.172): "0 when … the first frame is not HEADERS".
  - It feeds `connect_headers_complete` and `request_complete`.
  - `peek_decode_request` wraps `acc->buf` from offset 0. The non-CONNECT FIN path (`drive_complete` / `wired_h3reqdrive_recv_get`) should be checked for the same assumption.
- **Needed**: skip reserved and unknown frames (any type that is not DATA, HEADERS or a known request-stream frame) before HEADERS, both in completion detection and in decode.
- **Unblocks**: setup/announce/pnd/subscribe-error/sba for both clients, about 10 cases. announce-subscribe then still needs G1.

### G5. WT session close: no FIN or reset of the CONNECT stream after the peer's WT_CLOSE_SESSION. 6 cases (moq-playa; probable)

- **Spec**: draft-ietf-webtrans-http3 §6. A sender of WT_CLOSE_SESSION FINs the CONNECT stream, and the recipient must close or reset its side in response. The wired ledger has WTH3-067 as `[~]` covering only the send side.
- **Evidence**:
  - moq-playa (`@fails-components/webtransport`, quiche) `dist/teardown.js` calls `conn.close()` and then awaits `transport.closed` with a 3 s bound. All 6 cases fail with `teardown failed: transport close unsettled after 3000ms`, even though the functional checks passed.
  - The breakpoint trace shows wired calls `wired_moqt_on_session_close` but never `wired_server_wt_stream_fin`/`_reset`.
  - `srvrun_close_wt_session_slot` (`src/app/http3/server/srvrun/srvrun.c` ~l.3365) calls `srvrun_wt_connect_sender_drop`, which abandons the CONNECT-stream send slot without FIN, and then releases the slot.
  - Not verified on the wire, because the keylog is incomplete.
- **Needed**: on a received WT_CLOSE_SESSION, or a FIN on the CONNECT stream, send FIN (or RESET_STREAM) on the server's side of the CONNECT stream.
- **Unblocks**: setup/announce/pnd/subscribe-error/sba for moq-playa (5 cases). announce-subscribe still needs G1.

### G6. No raw-QUIC MoQT (ALPN `moqt-NN`, `moqt://`). 4 clients, about 19 cases

- **Evidence**:
  - imquic's ClientHello ALPN is `moqt-21,moqt-20,moqt-19,moqt-18,moqt-17,moqt-16`, with no h3, for `https://relay:4443`.
  - mlmtest's is `moqt-18` ("QUIC dial … ALPN moqt-18").
  - wired answers CONNECTION_CLOSE CRYPTO_ERROR 0x128.
  - moqtopus and xquic-draft-18 refuse the https:// URL themselves before dialing.
- **wired state**:
  - The server ALPN set is only h3 and hq-interop (`src/tls/ext/salpn/negotiate.c` `salpn_select_h3/_hq`, enum in `negotiate.h`).
  - There is no `moqt-` ALPN anywhere except the WT subprotocol table `src/app/moqt/ver/moqver.c:17-26`.
- **What it would take**:
  1. Add SALPN_MOQT_{18,19,22} in salpn (version taken from the ALPN).
  2. In srvrun, branch on `c->s.sdrv.alpn` like the existing hq-interop branch (`srvrun.c` ~l.6611): skip H3/QPACK and Extended CONNECT.
  3. Bind the connection to a hub "session" object. The hub io is keyed on `wired_wt_session*` (`moqtrun.h` io table: `open_bidi_stream`, `send_uni`, `stream_send`, `stream_fin`, `stream_reset`, …). A raw-QUIC session adapter would:
     - map these onto plain QUIC streams with no WT stream-type or session-id prefix;
     - use QUIC DATAGRAM frames without the quarter-stream-id;
     - take the first client bidi stream as the control stream;
     - handle the SETUP PATH/AUTHORITY parameters that raw QUIC needs.
  4. Register a second runner entry with `"url": "moqt://relay:4443"`, the way `aiomoqt-relay-quic` does.
- **Runner limitation**: a relay has a single `roles.relay.docker.url`, and the runner does not filter clients by transport for docker runs.
  - So all 14 clients are selected for wired.
  - imquic and moqlivemock dial raw QUIC even for https, so same-port ALPN dispatch would serve them under the current https registration.
  - moqtopus and xquic-draft-18 need a `moqt://` registration.
- **Minor compliance bug**: on an ALPN mismatch wired sends handshake_failure (0x128). RFC 9001 §8.1 requires no_application_protocol (0x178). No `no_application_protocol` alert exists in `src/tls`; `eebuild.c:43` returns 0 and the generic failure is used.

## 3. Failures judged client-side (or a runner limitation)

- **moq5 counted PASS while announce-subscribe failed**: the client exits 0 with a `not ok` line. Client bug (exit status). The failure itself is G1.
- **moq-dev-js announce-subscribe**: it treats REQUEST_ERROR 16 as ok. Client leniency. The underlying wired gap is G1.
- **moq-dev-rs subscribe-error / subscribe-before-announce SKIP**: the moq-net API cannot SUBSCRIBE without namespace discovery. Client limitation.
- **stitcher-moq subscribe-error / rendezvous-timeout SKIP**: moq-net answers unannounced paths locally and cannot set RENDEZVOUS_TIMEOUT. Client limitation.
- **moqtopus**: `moqtopus only supports raw QUIC relay URLs using moqt://`. **xquic-draft-18**: `draft-18 interop cases currently support raw QUIC (moqt://) only` (exit 127). Both reject the URL client-side, with no packets sent. They are not runnable against an https-registered relay, a runner and registration limitation, even after G6.
- **imquic and moqlivemock**: both dial raw QUIC with moqt ALPNs regardless of the https:// scheme. That is client-side transport selection; on wired's side it is G6. moqlivemock's own registry note says "mlmtest dials raw QUIC".
- **Local-only artifacts, not wired bugs**:
  - In this sandbox (no IPv6), moq5 natively fails with "failed to create endpoint" (picoquic needs a v6 socket), and moq-dev-js/moq-rs native panic with EAFNOSUPPORT.
  - With the shim, aiomoqt and moxygen fail to connect.
  - All of these were resolved by picking native or shim per client.
  - In CI (IPv6) the pass/fail set is identical to the final local run.
